[2026-02-21 18:10] GPU IDLE USAGE - CRITICAL DISCOVERY
Status: RESOLVED

Problem Discovered:
After GPU detection working, noticed GPU stayed at 100% even when model idle:
```
$ ollama ps
NAME           ID       SIZE    PROCESSOR    UNTIL
llama3.2:3b    ...      2.8GB   100% GPU     Forever

$ cat /sys/class/drm/card1/device/gpu_busy_percent
100   # Constantly 100% even with no inference!

$ rocm-smi
Power: 92W, GPU: 100%, Temp: 47°C
```

Root Cause Analysis:
1. OLLAMA_KEEP_ALIVE=-1 kept model loaded forever
2. Loaded model on GPU consumed 100% utilization even when idle
3. Resource manager couldn't distinguish idle Ollama from gaming
4. resource-manager.sh loaded model on startup → instant false "gaming" detection
5. Wasted 52W power (96W vs 44W idle)

Architectural Flaw:
- Assumed: "keep model loaded = faster responses"
- Reality: "keep model loaded = broken gaming detection + wasted power"
- 2-second model load time is acceptable for home automation

Solution Implemented:
1. Removed OLLAMA_KEEP_ALIVE=-1 from ollama.service (uses default 5min)
2. Removed keep_alive:-1 from resource-manager.sh API calls
3. Removed load_small_model() from resource manager startup
4. Removed load_small_model() from exit_gaming_state
5. Result: On-demand loading, GPU idles at 0% when no models loaded

Fixed Behavior:
```
# System idle (no models loaded)
$ ollama ps
NAME    ID    SIZE    PROCESSOR    UNTIL

$ cat /sys/class/drm/card1/device/gpu_busy_percent
0-2   # Properly idle!

$ rocm-smi
Power: 44W, GPU: 0%, Temp: 38°C

# After inference
$ ollama run llama3.2:3b "test"
ok

$ ollama ps
NAME           ID       SIZE    PROCESSOR    UNTIL
llama3.2:3b    ...      2.8GB   100% GPU     5 minutes from now

# Model auto-unloads after 5 min idle
# GPU returns to 0%, power to 44W
```

Benefits:
✓ Gaming detection works (can distinguish idle vs gaming)
✓ Saves 52W power when idle
✓ Hysteresis (30s enter, 5min exit) prevents false gaming detection
✓ Home automation: 2s first request, instant subsequent (while model loaded)
✓ Batch jobs: Model stays loaded during processing (no reload overhead)

Files Modified:
- resource-manager-v2.sh: Removed startup loading, removed keep_alive:-1
- ollama.service: Removed OLLAMA_KEEP_ALIVE=-1

Lesson Learned:
Premature optimization is the root of all evil. Keeping models loaded "for speed"
broke the core gaming detection feature and wasted power. On-demand loading with
5-minute timeout is the right balance.

Architecture Decision: Tier 1 (MVP)
After discovering the complexity, decided on tiered approach:
- **Tier 1 (MVP):** Current system - preempt all batch jobs, on-demand loading
- **Tier 2 (Configurable):** --preempt / --no-preempt / --queue flags
- **Tier 3 (Production):** Checkpointing, priority queues, web UI, persistence

Documentation Created:
- TIER-2-IMPLEMENTATION-PLAN.md (detailed plan for configurable preemption)
- TIER-3-IMPLEMENTATION-PLAN.md (production-grade orchestration platform)
