# Plan: Per-Model Upstream Backend Routing

## Approach

Add a small, explicit "one model → one alternate backend instance" routing table, resolved once at `config.Load()` time from a bounded set of indexed env vars (`BROKER_ROUTE_1_*`, `BROKER_ROUTE_2_*`, …), and dispatch on it with a thin `Router` that wraps the existing default `Backend` plus one constructed `Backend` per configured route. `Router` implements the existing `backend.Backend` interface unchanged, so every downstream consumer of `Backend` (the Gate, the Job worker, `/healthz`) keeps working against the same seam it already knows. `Router` is only constructed and used when at least one route is configured (`len(cfg.Routes) > 0`); when no routes are configured, `cmd/broker/main.go` bypasses `Router` entirely and wires `defaultBackend.Proxy()` directly to both gates, exactly as it does today — zero `Router` construction, zero body-peeking, zero behavior change from the pre-feature code path. The one real architectural change is `yield.Controller`, which today assumes exactly one `Unloader`; it is generalized from a single `(unloader, actionDone)` pair to parallel slices, one independent ADR-0014 ordering chain per configured instance, added via new `*Multi` constructors that don't touch the existing single-instance constructors' signatures or behavior. This keeps the blast radius small: `internal/config`, one new file in `internal/backend`, an additive change to `internal/yield`, and wiring in `cmd/broker/main.go`.

## Architecture

The embed lane (ADR-0008) is a real precedent for "a second upstream sharing the yield Controller," but it doesn't fit here: it works because Infinity gets its own dedicated port (`:11438`) that consumers deliberately point at. This feature's FR-3/FR-5 require routing by **model name on the existing Interactive/Batch ports**, transparently, with FR-17 guaranteeing Consumers never need to know which backend instance served them. A second port would force every consumer of a routed model to be reconfigured to a new address — exactly the "operator burden + consumer awareness" the requirements rule out. So routing has to happen *inside* the existing lanes, per request, based on the `model` field — a dispatch-table problem, not a second-lane problem. The embed lane's other idea — "share the yield Controller, don't share the concurrency slot" — does carry over directly: routed requests still go through the *same* Interactive/Batch `queue.Scheduler`/Gate (GPU concurrency, yield, park behavior all unchanged; ADR-0003/0004 apply identically to every instance, satisfying FR-14/AC-12), only the final hop (which `Backend.Proxy()`/`Generate()` handles the request) is chosen per model.

```
                 ┌──────────────────────────────────────────────────────────┐
                 │ cmd/broker/main.go                                       │
                 │  defaultBackend := backend.New(cfg)                      │
                 │                                                          │
                 │  if len(cfg.Routes) == 0:                                │
                 │    // no Router constructed at all — zero body-peeking   │
                 │    interactiveGate.Proxy = defaultBackend.Proxy()        │
                 │    batchGate.Proxy      = defaultBackend.Proxy()         │
                 │    ctrl := yield.NewWithConfirm(det, defaultBackend      │
                 │            .Unloader(), interval, confirm)   (unchanged) │
                 │                                                          │
                 │  else:                                                   │
                 │    routeBackends, routeUnloaders :=                      │
                 │        buildRoutes(cfg.Routes)   (single index-aligned   │
                 │                                    builder — see below)  │
                 │    router := backend.NewRouter(defaultBackend,           │
                 │                cfg.Routes, routeBackends)                │
                 │    unloaders := append([]yield.Unloader{                 │
                 │        defaultBackend.Unloader()}, routeUnloaders...)    │
                 │    ctrl := yield.NewWithConfirmMulti(det, unloaders,     │
                 │            interval, confirm)                            │
                 │    interactiveGate.Proxy =                               │
                 │        router.ProxyForLane(queue.Interactive.String())   │
                 │    batchGate.Proxy =                                     │
                 │        router.ProxyForLane(queue.Batch.String())         │
                 └───────────────┬──────────────────────────────────────────┘
                                  │
        job.Worker (Generator) ───┼──── router.Generate(ctx, model, ...)    (routed case only;
        /healthz healthCheck ─────┼──── router.Reachable(ctx)  (default only)  defaultBackend
        /status ──────────────────┴──── router.RoutingSummary()                otherwise)

   router.ProxyForLane(lane string) http.Handler:
     [only reached when len(cfg.Routes) > 0]
     size-capped peek of "model" from JSON body (read at most the first 64KB,
     or a streaming json.Decoder that stops once "model" is found; buffer the
     bytes consumed and restore them via io.MultiReader before forwarding —
     only the 3-line buffer-and-restore *shape* is borrowed from proxy.go's
     retryTransport, not its size assumptions or GetBody/replay mechanism,
     since retryTransport buffers an OUTBOUND client request for
     transport-level retry-replay, a different problem from Router's single
     inbound peek-then-restore with no replay) → table lookup (model[, lane])
     → resolved Backend.Proxy().ServeHTTP(w, r)   [unmatched → default]

   yield.Controller (generalized):
     unloaders []Unloader            (compact, non-nil only)
     actionDone []chan struct{}      (one independent chain per index)
     applyLocked: for i := range unloaders { go doUnload/doReload(i, startAction(i)) }
```

When `len(cfg.Routes) == 0` (the default, and today's behavior), `main.go` never constructs a `Router` at all — both gates get `defaultBackend.Proxy()` directly, exactly as before this feature, satisfying AC-1's byte-for-byte requirement with zero added cost (no body-peeking, no extra allocation, no extra branch in the hot path). When one or more routes are configured, every request — including unrouted models — passes through `Router.ProxyForLane`, which does a size-capped peek of the `model` field before falling through to the default backend for anything that doesn't match a route; this is still a pure in-memory lookup with a bounded (not unbounded) buffering cost, never a network round trip, and never a full-body read of a large vision payload.

## Data model

No data model changes. The durable Job store's `Model` column (`internal/job`) already exists and is unmodified; `Router.Generate` uses the same `j.Model` value the worker already passes today. No new SQLite tables, no schema migration.

## API / interface contract

**New env vars** (indexed 1..N, scanned up to a bounded ceiling of 32 — an unset `BROKER_ROUTE_1_MODELS` means routing is fully disabled, matching the `UPSTREAM_UNIT_NAME` empty-disables-it precedent, FR-9/AC-5; any index below the highest configured index that has no `_MODELS` set is a startup error — an index *gap* — not a silent stop, so deleting route 2 while keeping route 1 and route 3 configured fails `Load()` loudly instead of silently limiting the table to route 1 or, worse, to nothing):

| Var | Default | Meaning |
|---|---|---|
| `BROKER_ROUTE_<N>_MODELS` | _(unset)_ | Comma-separated model name(s) routed to this instance. Unset/empty at N=1 disables routing entirely |
| `BROKER_ROUTE_<N>_BACKEND` | `openai` | Backend family for this instance: `ollama` or `openai`, same values as `UPSTREAM_BACKEND` |
| `BROKER_ROUTE_<N>_URL` | _(required)_ | Base URL for this instance, validated scheme+host like `OLLAMA_URL`/`UPSTREAM_URL` |
| `BROKER_ROUTE_<N>_API_KEY` | _(unset)_ | Bearer token for this instance (openai family only). Never logged; CR/LF-rejected like `UPSTREAM_API_KEY` |
| `BROKER_ROUTE_<N>_UNIT_NAME` | _(unset)_ | Systemd unit for this instance's Unloader. Empty disables the Unloader for this instance only, same precedent as `UPSTREAM_UNIT_NAME` |
| `BROKER_ROUTE_<N>_LANE` | _(unset = both)_ | Optional: `interactive` or `batch` to scope this rule to one lane. Any other value is a startup error |

**Validation (config.Load(), fail-fast, all-or-nothing — AC-4):**
- Each `BROKER_ROUTE_<N>_URL` must parse with scheme+host (shared helper with `OLLAMA_URL`/`UPSTREAM_URL`).
- Each `BROKER_ROUTE_<N>_BACKEND` must be `ollama`|`openai`.
- Each `BROKER_ROUTE_<N>_LANE` must be `""`|`interactive`|`batch`.
- `BROKER_ROUTE_<N>_API_KEY` rejects CR/LF (same rule as `UPSTREAM_API_KEY`).
- A model name may appear in **at most one** route rule, full stop — not just "not mapped to two different targets within the same lane." This is a deliberate simplification over allowing the same model split across lanes to different backends: it removes an otherwise-real ambiguity for the Job path (jobs have no lane — see Risk areas), keeps the config trivially easy to reason about (one model → one place, always), and is squarely inside what the requirements already ask for ("out of scope: load balancing/splitting a single model's traffic across multiple backend instances").
- An empty model name mapped to a non-empty target, or a route with `_MODELS` set but a malformed `_URL`, fails `Load()` before any Config is returned — no partially-applied routing.
- No two instances (the default backend and/or any configured route) may resolve to the same `_UNIT_NAME` or the same backend URL — each independently-unloaded instance must map to a genuinely distinct physical/systemd resource, or two independent ADR-0014 ordering chains could issue `systemctl stop`/`start` against the same unit out of order (see Risk areas — this is a one-way-door check if it ships missing).
- Route indices must not contain a gap: scanning 1 through 32, any index below the highest index that has a route configured is itself required to have `_MODELS` set, or `Load()` fails — this is what makes "fail-fast, all-or-nothing" actually hold when an operator deletes a route without renumbering the rest (also a one-way-door check — see Risk areas).

**`/status` response** gains an optional `"routing"` key (array of `{models: [...], backend: "openai", url: "...", lane: "interactive"|"batch"|"", reachable: true|false}`, no API key ever included) **only when routes are configured** — omitted entirely otherwise, preserving AC-1's identical-shape requirement. The `reachable` field is per-route liveness (checked live or cached from the last attempt), distinct from the broker's own `/healthz` (which stays bound to the default backend only — see the `router.go` integration point below). Wired the same way `tdarr`/`jobs` are already conditionally added to `/status`'s output map.

**Startup log**: one `slog.Info("routing configured", "routes", [...])` line summarizing model→backend→lane, credential-free (FR-16/AC-11).

**Consumer-facing HTTP contract**: unchanged. Same Ollama API on `:11435`/`:11436`; error bodies from a routed backend pass through unmodified (FR-7/AC-9).

## Technology choices

- **Indexed env vars over a JSON/YAML blob in one var.** A single `BROKER_ROUTES=...` blob would be a new config format smuggled inside an env var, inconsistent with `config.go`'s all-scalar convention and its `getenv`/`getdur`/`getint` helpers. Indexed keys (`BROKER_ROUTE_1_*`, `_2_*`, …) stay in that same idiom and are trivially fail-fast validatable field-by-field, at the cost of being slightly more verbose per instance — acceptable given the NFR's bound of at most 16 simultaneously configured alternate instances.
- **Size-capped body buffer-and-restore for model-peeking — only the 3-line buffer-and-restore *shape* borrowed from `retryTransport` in `internal/proxy/proxy.go`, not its size assumptions or its GetBody/replay mechanism.** `retryTransport` buffers a full OUTBOUND client request body and reinstalls it via `GetBody` specifically to support transport-level retry-replay; its own comment justifies the unbounded read by asserting "Ollama/Infinity request bodies here are small JSON payloads" — an assumption that does not hold for inbound vision requests (base64-encoded images from `qwen3-vl`/`qwen2.5vl` traffic can run tens of MB). `Router.ProxyForLane` instead does a single inbound peek-then-restore, capped at reading the first 64KB (or via a streaming `json.Decoder` that stops once the `model` field is found), with no replay semantics at all — a materially simpler and safety-bounded version of the idiom, not a reuse of `retryTransport` itself.
- **Slice generalization in `yield.Controller` over an errgroup/worker-pool library.** No new dependency: parallel slices of `Unloader`/`actionDone` plus `go` + `startAction`'s existing channel-handoff idiom, applied per-index, is the minimal diff that preserves ADR-0014's exact per-instance ordering guarantee. Pulling in `golang.org/x/sync/errgroup` or similar would add a dependency for something the existing hand-rolled channel-chain pattern already does correctly per instance.

## Risk areas

- **`yield.Controller` generalization is the highest-risk change in this plan.** It touches the single most safety-critical file in the repo (the gaming/Plex hard-yield path, ADR-0003/0004/0014). The per-index independence claim (FR-13: one instance's failure never blocks another) needs to be proven, not assumed — the new multi-instance flap test must assert that a permanently-erroring `Unload`/`Reload` on instance A does not delay or reorder instance B's actions, not just that both eventually fire.
- **Job-path lane semantics are underspecified by the requirements and resolved here by judgment, not restated from the spec.** Jobs (`POST /jobs`) have no lane at all, so this plan makes a lane-scoped rule apply unconditionally on the Job path regardless of its lane scope (see API contract section) and additionally forbids splitting one model across lanes to different targets, to avoid the ambiguity entirely. This is the one place a reviewer should double-check intent against FR-4/FR-5 before building.
- **Model-peek buffering must be verified against every real Ollama request shape** (streaming `/api/generate`, `/api/chat`, `/api/embed` batches, and vision requests carrying base64 image payloads from `qwen3-vl`/`qwen2.5vl` traffic) to confirm (a) zero behavior/perf change when routing is disabled — now structurally guaranteed by the zero-route bypass in `main.go`, which never constructs a `Router` or peeks a body at all (AC-1) — and (b) the size-capped peek (first 64KB, or a streaming decoder that stops at the `model` field) actually stays bounded under a real oversized vision payload when routes ARE configured but the request's model isn't routed (the common case within a routed deployment, since the peek still runs to check the table even for unrouted models) — this needs a real test with an oversized body, not just a unit test against a small JSON fixture.
- **Same-physical-resource validation (rejecting two instances sharing a `_UNIT_NAME` or URL) is a one-way door if missed.** A config mistake that maps two routes (or a route and the default) to the same underlying systemd unit or backend URL would ship clean — nothing fails locally — and only surface in production as two independent ADR-0014 ordering chains issuing `systemctl stop`/`start` against the same unit out of order, reintroducing exactly the race ADR-0014's fix was built to prevent. This can only be caught by validation at config time (see `internal/config/config.go` bullet above); there is no runtime signal that would catch it after the fact, and no cheap way to add the check retroactively once instances are already running independent unload chains against a shared resource. It ships with this feature or it doesn't get caught until an operator sees exactly the symptom ADR-0014 exists to prevent.
- **Index-gap validation in the `BROKER_ROUTE_<N>_*` parse loop is also a one-way door if missed.** Without it, an operator deleting route 2 (while keeping 1 and 3) gets silent, wrong behavior — the table quietly shrinks to "only route 1 configured" (or worse) with no startup error — rather than the fail-fast, all-or-nothing behavior this plan promises elsewhere (AC-4). Like the same-resource check, this has to be caught at `Load()` time; once shipped without it, the failure mode is invisible until an operator hits it by making an ordinary config edit.
- **`internal/acceptance_test.go`'s `newRig` going stale is a named risk, not just a housekeeping note.** If `newRig` isn't updated to build Gates via `Router` (per the new main.go wiring) once routes exist, the entire acceptance suite keeps passing while silently no longer exercising the real production wiring path — no test failure signals this, since `newRig`'s pre-feature mirror still compiles and its assertions still hold against itself. See the dedicated `internal/acceptance_test.go` integration point bullet above.
- **`Router.Unloader()` returning a bare `nil` is a deliberate, documented trade-off, not an oversight** — a narrower custom interface was considered and rejected as unnecessary churn for a pre-ship decision (see the `router.go` integration point bullet). It is still worth flagging in code review: a future contributor treating `Router` as an ordinary `Backend` (e.g. in a new test or a refactor) could reasonably expect `Unloader()` to mean something, and the doc comment mitigates but doesn't eliminate that risk. `docs/adr/0015` records the reasoning explicitly so this isn't mistaken for an oversight by a future reader.
- **Startup validation has several interacting failure modes in one `Load()` pass** (malformed URL, empty model, duplicate model, bad lane value, CR/LF in API key, a same-`_UNIT_NAME`/URL collision across instances, an index gap in the route table) — AC-4 requires the process to fail to start on any of them with zero partial application, which means `Load()` must validate every route before constructing/returning any `*Config`, not fail partway through a loop after already committing earlier routes. Needs deliberately adversarial table-driven tests, not just happy-path coverage.
- **Minor: `admin.Mux`'s parameter list is gaining its 9th positional, loosely-typed argument** (`routingStatus func() any`, alongside `jobStatus func() any` and others) — a documented fragility (argument-order mistakes at the single call site aren't caught by the compiler). Explicitly out of scope to fix via an options-struct refactor in this feature.
