## CONTEXT.md
Resource Broker: a Go program controlling GPU access on a home desktop shared by gaming, Plex transcoding, and Ollama/vLLM inference. Gaming and Plex always win. Glossary terms: Broker, Contention, Yield (whole-Broker refusal state during Contention), Preemption (interrupting one in-flight request), Job (durable batch work, survives restart), Queue, Park/Parked request, Fronting Proxy (entry point for live requests, speaks Ollama's HTTP API), Synchronous request, Embed lane (an optional second upstream server on its own port, :11438, shares the Yield controller but not the GPU concurrency slot — closest existing precedent to a second upstream lane, though this feature's plan explicitly rejected the second-port model in favor of same-port model-name dispatch), Consumer (any service sending requests through the Broker: internal-monitor-app, LightRAG, internal-scraper-service vision, one-off CLI jobs).

## Spec-gather notes
- Requirements: 17 functional, 5 non-functional, 13 acceptance criteria — clean coverage-checked against steps.md (0 gaps).
- Plan's central design call: reject the embed-lane (second-port) precedent in favor of a same-port, per-model routing table (`Router` type implementing the existing `Backend` interface), because FR-3/FR-5/FR-17 require Consumer-transparent routing on the existing Interactive/Batch ports.
