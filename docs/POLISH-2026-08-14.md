# Maintainability polish pass — 2026-08-14

Cost-no-object polish pass on live GPU-arbitration infrastructure. Scope,
findings, and what was (and was not) changed.

## Repo/language

Go 1.24, single static binary (`cmd/broker`), pure-Go SQLite driver
(`modernc.org/sqlite`, no CGO). Tooling used: `go build`, `go vet`,
`gofmt`, `golangci-lint run` (errcheck etc. — not part of this repo's own
CI, which only runs build/vet/test; used here as a diagnostic sweep, not
an enforced gate), `go run golang.org/x/tools/cmd/deadcode`, `go test
-race ./...`.

## Architecture check (per the task brief)

The brief asked me to verify a secondhand description ("wraps CLI batch
jobs and cgroup-throttles Ollama") against the real, current
implementation before trusting it. That description is **stale** — it
describes the old Bash V3 daemon (`legacy/resource-manager-v3.sh`), kept
in `legacy/` for reference only and explicitly documented as "must never
run alongside the Broker." The current (v2, live) architecture is an
**HTTP-fronting reverse proxy** in Go:

- `internal/detect` + `internal/yield`: process-name contention detection
  (gaming/Plex) → binary yield, with Plex-session corroboration and
  debounced confirmation (ADR-0003, ADR-0012).
- `internal/queue`: a priority scheduler (`Scheduler.Gate`) — one GPU
  slot (`MaxInflight`, default 1, ADR-0004), interactive jumps batch,
  FIFO within a class, plus a bounded FIFO "park" queue for batch
  requests caught mid-yield (ADR-0009).
- `internal/proxy`: a streaming reverse proxy to real Ollama (and
  optionally an Infinity embedding lane), with a bounded-retry transport
  for connection-level upstream flakiness.
- `internal/job`: a separate, SQLite-durable batch-Job queue/worker that
  shares the same scheduler and yield gate (ADR-0006/0007) — this is the
  only "queue that survives a restart" piece, and it is not a cgroup
  throttle either; preemption/backoff both work by cancelling a Go
  context.

No cgroups anywhere in the current code. Port routing matches the house
convention exactly: `:11435` interactive, `:11436` batch, `:11437`
control/admin, optional `:11438` CPU embed lane — confirmed by reading
`internal/config/config.go` defaults and the wiring in
`cmd/broker/main.go`.

## What I found

The codebase is already unusually disciplined: nearly every non-obvious
line has a comment tracing back to a dated audit or an ADR (0001–0013),
`go vet` was clean, `gofmt` was clean except one file (below), and the
full test suite (including `-race`) was green before I touched anything.
There was very little to polish.

- `golangci-lint run` (errcheck): 44 unchecked-error findings. Almost all
  are standard, low-risk Go idioms this repo already leans on elsewhere
  (`defer tx.Rollback()` after a commit, `defer rows.Close()`,
  `resp.Body.Close()`, writes to an HTTP response after headers are
  already committed, test-helper assertions). Reviewed each one;
  left as-is except the two described below, which had genuine
  observability value.
- **Duplicate `writeJSON` helper**: `internal/admin/admin.go` and
  `internal/job/api.go` each defined a byte-identical 4-line
  `writeJSON(w, code, v)` — and both silently dropped the
  `json.Encoder.Encode` error. A silently-dropped encode error on this
  service's own control/status/job API is exactly the "error swallowed
  instead of logged" class of bug the brief called out as highest
  priority. Fixed by extracting one shared `internal/httpx.WriteJSON`
  (new, single-function package) used by both, which now logs via
  `slog.Warn` on an encode failure.
- **`store.Close()` on shutdown** (`cmd/broker/main.go`): the durable Job
  SQLite store's close error was discarded. Now logged via
  `slog.Warn("job store close", "err", err)` on the shutdown path.
- **gofmt**: `internal/queue/park.go` had a struct-field alignment glitch
  (comment inside the field block broke gofmt's column alignment).
  Whitespace-only fix, `gofmt -w`.
- **`deadcode`**: flagged `yield.New` as unreachable from the production
  binary. Checked it before touching anything — it's exported, documented
  ("the historical, pre-debounce behavior... NewWithConfirm requires
  sustained detection"), and exercised directly by `yield_test.go`. Not
  dead code in the "clutter" sense the brief cares about; it's a
  deliberate, tested, simpler constructor kept for API completeness.
  **Left as-is.**

## Explicitly reviewed and NOT touched — arbitration/queueing/throttling

Per the brief, I read `internal/queue/scheduler.go`, `gate.go`, `park.go`,
`internal/yield/yield.go`, `internal/job/worker.go`, and
`internal/job/service.go` in full. All of it is core arbitration logic:
slot acquisition/release, priority-class FIFO, the park/drain bounded
queue, yield debounce/confirm-polls, and batch-preemption-past-quantum.
I found no bugs and no unambiguous readability win worth the blast
radius. **I made zero changes here.** Nothing here needs escalating
either — there's no ambiguous case I stopped short of; there was simply
nothing to fix.

## Deploy note (not done, per instructions)

This pass did **not** restart or redeploy the live broker — it is
running right now and every LLM-calling service in the house depends on
it. Deploying would mean: rebuild the binary
(`make build` / `CGO_ENABLED=0 go build -o bin/ollama-broker ./cmd/broker`),
stop the running `ollama-broker` systemd unit, replace the binary, restart
the unit, and re-verify `/healthz` on `:11437` plus a live request through
`:11435`/`:11436` before considering it done. That should be its own
deliberate, separately-approved step — not a side effect of a polish
pass.
