# Requirements: vLLM/OpenAI-backend VRAM-yield Unloader

## Problem statement
When gaming or Plex transcoding contention appears, the Broker must yield hard per ADR-0003: cancel the in-flight request and force the upstream to release VRAM. ADR-0003's forced-unload half is implemented for the Ollama backend only; `internal/backend/openai_backend.go`'s `Unloader()` unconditionally returns `nil`, so an openai-backend upstream (e.g. vLLM) keeps its model resident in VRAM through contention, starving the game — a live violation of the yield invariant for any deployment routed through this backend. This matters now because vLLM is being provisioned as a second inference upstream on desktop (<broker-host>); without this fix, turning on the openai backend regresses the one invariant the Broker exists to enforce.

An earlier draft of this spec mandated `systemctl restart <unit>` on yield-start only. Adversarial design review rejected that mechanism: `restart` = stop-then-start, so systemd eagerly reloads the model and re-claims GPU memory a few seconds later, regardless of whether gaming contention is still active. VRAM is freed for a brief gap and then re-occupied for the rest of the gaming session — functionally the same failure ADR-0003 already named and rejected as "cancel-but-leave-loaded" (VRAM stays occupied, game still contends), just delayed by a few seconds. This spec instead mandates a symmetric stop/start mechanism, mirroring Ollama's real behavior: unload on yield-start, lazy-reload only when serving resumes.

## Users / stakeholders
- Broker operator (Preston) — configures and deploys the Broker on desktop; needs the invariant enforced the moment the openai backend goes live.
- Gaming/Plex sessions — the priority claimants ADR-0003 protects; indirectly depend on VRAM actually being freed on yield, for the full duration of contention, not just briefly.
- Consumers of Synchronous/Job inference (fashion-monitor, LightRAG, estate-scraper, etc.) — experience the reload latency cost this mechanism trades for a clean GPU, including connection errors while the unit is down or restarting.
- Future maintainers — read the Unloader() code and its typed-nil contract, plus the new Unload/Reload symmetry, when adding or modifying backends.

## Functional requirements
1. The system shall read a new environment variable (`UPSTREAM_UNIT_NAME`) at config load time and expose it as a new string field on the existing `Config` struct in `internal/config/config.go`, populated in `Load()` following the exact pattern already used for `UpstreamURL`/`UpstreamAPIKey`.
2. The system shall trim `UPSTREAM_UNIT_NAME` of leading/trailing whitespace before evaluating whether it is empty; a whitespace-only value shall be treated identically to an empty/unset value.
3. The system shall, when the trimmed `UPSTREAM_UNIT_NAME` is empty, return a literal `nil` of the `yield.Unloader` interface type from `openaiBackend.Unloader()` — never a typed-nil-wrapped pointer — preserving today's exact no-op behavior.
4. The system shall, when the trimmed `UPSTREAM_UNIT_NAME` is non-empty, return a non-nil `yield.Unloader` implementation from `openaiBackend.Unloader()`.
5. The system shall, when that Unloader's `Unload` is invoked on yield-start, execute `systemctl stop <UPSTREAM_UNIT_NAME>` (the configured unit name substituted verbatim, no other interpolation) — not `restart` — so the unit remains stopped for the full duration of the contention window instead of being eagerly reloaded by systemd.
6. The system shall extend the `yield.Unloader` Go interface in `internal/yield/yield.go` with a second method, `Reload(ctx context.Context) error`, invoked on the yield-clear transition symmetric to the existing `Unload` call on yield-start.
7. The system shall, when the openai-backend Unloader's `Reload` is invoked on yield-clear, execute `systemctl start <UPSTREAM_UNIT_NAME>` against the configured unit, bringing vLLM back up so it reloads the model.
8. The system shall add a no-op `Reload(ctx context.Context) error` implementation to `ollama.Client` (returns `nil` immediately, executes no command and makes no network call) to satisfy the widened `yield.Unloader` interface — Ollama's real "reload" is implicit/lazy on its next generate call, so there is nothing to actively trigger.
9. The system shall invoke both the `systemctl stop` and `systemctl start` calls through a command-runner seam narrowed to "run systemctl with one of exactly two verbs (stop/start) against this one configured unit" — not a fully generic run-any-command-with-any-args function — so it can be substituted with a stub or mock in tests without depending on a real `systemctl` binary or a running systemd instance.
10. The system shall rename the openai-backend Unloader implementation type (it is no longer a single-action "systemctlUnloader" performing one restart; it now handles both stop and start) and shall internally serialize `Unload` and `Reload` calls for the same unit with a mutex or equivalent, so a yield-clear/yield-start flap can never race a `systemctl start` against a `systemctl stop`.
11. The system shall have the openai-backend `Unload` and `Reload` implementations return real, non-swallowed errors on `systemctl stop`/`start` failure. No new logging call sites are added by this feature: `yield.go`'s existing `doUnload` and new `doReload` functions already log success (INFO, e.g. "vram unload requested" / analogous for reload) and failure (WARN, matching `doUnload`'s existing `slog.Warn` call — not ERROR) generically for any `Unloader`, Ollama or openai alike; returning real errors is sufficient for that shared logging to fire correctly.
12. The system shall NOT call vLLM's native `/sleep` or `/wake_up` endpoints as part of this mechanism, under any configuration.
13. The system shall leave `openaiBackend.Unloader()`'s behavior unchanged for every existing deployment where `UPSTREAM_UNIT_NAME` is empty, unset, or whitespace-only — returning a literal nil `yield.Unloader`, identical to today's unconditional-nil behavior, verified by the same direct nil-interface-equality test style already in the codebase.
14. The system shall document `UPSTREAM_UNIT_NAME` in the README config table with its name, purpose, and default (empty/unset = disabled).
15. The system shall include `UPSTREAM_UNIT_NAME` (unset/empty by default) in `deploy/broker.service`, consistent with how other optional config-axis env vars are represented there.
16. The system shall document `UPSTREAM_UNIT_NAME` in the same config-flags doc that `internal/config/config.go`'s other env vars are documented in (per the broker-change-control new-config-axis gate).
17. The system shall be covered by unit tests in `internal/config/config_test.go` for the set, unset/empty, and whitespace-only states of `UPSTREAM_UNIT_NAME`.
18. The system shall extend the shared timeout in `yield.go` (currently 10 seconds, applied to every `Unloader.Unload` call in `doUnload`) so it also applies to the new `doReload` counterpart, as a single shared constant — widened somewhat from 10s, since that value was sized for Ollama's near-instant HTTP unload call, not a systemd process stop/start. A per-backend configurable timeout is explicitly not required.
19. The system shall document, via a code comment near the shared timeout constant, that the client-side `exec.CommandContext` timeout is a give-up bound only: killing the CLI process at timeout does not cancel the underlying systemd job (systemctl talks to PID 1 over D-Bus), so timeout expiry does not guarantee the stop/start operation actually stopped or completed.
20. The system shall update the doc comment on `internal/backend/backend.go`'s `Unloader()` interface method so it no longer implies every backend always returns nil. It must still require that nil-when-applicable be a literal nil (never a typed-nil concrete pointer), but must not state or imply that the openai backend always returns nil.

## Non-functional requirements
- No live systemd or vLLM process may be required for `go test ./...` to pass for this feature's code paths — the `systemctl stop`/`start` calls must be mockable/stubbable in-process.
- `go test ./...` and `go vet ./...` must report no new failures versus `main` (the pre-existing unrelated `internal/admin` test-signature mismatch is explicitly out of scope and must not be touched).
- The typed-nil safety discipline documented in the current `Unloader()` comment must hold for all code paths, including the new configured branch — a nil-interface check in `yield.go` must never see a typed-nil concrete pointer.
- Error handling for the stop/start calls must not introduce new logging call sites: correctness means `Unload`/`Reload` return real, non-swallowed errors so the existing shared logging in `yield.go`'s `doUnload`/`doReload` (INFO on success, WARN on failure) fires correctly for both `ollamaBackend` and `openaiBackend`.
- `Unload` and `Reload` for the same unit must never execute concurrently — the implementation must serialize them (e.g. via a mutex) so a yield-clear/yield-start flap cannot race `systemctl start` against `systemctl stop`.

## Constraints
- Must integrate with the existing `yield.Unloader` interface as consumed by `internal/yield` (`yield.go`'s nil-guard pattern: `if c.unloader != nil { go c.doUnload() }`, mirrored for the new reload path). The interface is extended with exactly one new method (`Reload`) per FR6 — no other change to its shape.
- This is a scheduler/yield-invariant change already under broker-change-control's highest gate (ADR + tests required); extending the `yield.Unloader` interface does not trigger a new gate — it is a larger diff under the same gate.
- Must follow this repo's broker-change-control skill: a new config axis requires `internal/config/config.go`, `internal/config/config_test.go`, the README config table, `deploy/broker.service`, and the config-flags doc to be touched together in the same change.
- This is a scheduler/yield-invariant-adjacent change per broker-change-control's highest gate: requires a one-page ADR in `docs/adr/` (decision + rejected alternatives) referencing ADR-0003 and ADR-0004, delivered before or with the code.
- The invariant itself (gaming has absolute priority) may not be weakened by this change — only the openai backend's implementation of it is being completed.
- Mechanism is mandated: symmetric `systemctl stop` (yield-start) / `systemctl start` (yield-clear) against the configured unit, mirroring Ollama's real unload-then-lazy-reload behavior — not `systemctl restart` (restart eagerly reloads the model within a few seconds regardless of whether contention is still active, recreating the same VRAM-recontention failure ADR-0003 already named and rejected as "cancel-but-leave-loaded," just delayed), and not vLLM's `/sleep`+`/wake_up` API (rejected per vllm-project/vllm#20627, an open, unresolved bug causing corrupted output on the OpenAI-compatible-server path after repeated sleep/wake cycles, research-confirmed 2026-08-15).
- The broker's service user requires a sudoers/polkit rule scoped to stop/start (and, if applicable, restart) ONLY the one configured unit — never a wildcard grant. This scope must be documented/recommended explicitly in the ADR delivered with this change; provisioning the actual host rule is out-of-repo operator work (see Out of scope).
- While the unit is stopped (during contention) and while it is starting back up (immediately after contention clears), Consumer requests routed to the openai backend will fail with connection errors, surfaced via the Broker's existing retry/backoff. This is expected, accepted behavior for this mechanism and must be documented explicitly in the ADR/acceptance criteria — not treated as a gap to close.
- This ships resource-broker application code only. Provisioning a real vLLM systemd unit on desktop (<broker-host>), and provisioning the host sudoers/polkit rule, are separate, out-of-repo work and are not dependencies for this feature's code to merge.

## Out of scope
- Provisioning, installing, or configuring an actual vLLM systemd unit, or the host sudoers/polkit rule, on desktop or any other host.
- Any change to `ollamaBackend`'s existing `Unload` behavior (the new no-op `Reload` addition required by FR8 is in scope; `Unload` itself is unchanged).
- Any change to the `yield.Unloader` interface's shape beyond the single `Reload` method addition specified in FR6.
- Support for vLLM's `/sleep` and `/wake_up` API as an unload mechanism.
- Fixing the pre-existing, unrelated `internal/admin` test-signature mismatch.
- Automatic discovery or validation that the configured systemd unit actually corresponds to a running vLLM/OpenAI-compatible process (the operator is responsible for correct configuration).
- Full systemd-unit-name syntax validation beyond the whitespace-trim fix in FR2 (operator responsibility).
- A startup-time preflight check (e.g. `systemctl show <unit>` at broker startup) validating the unit exists/is reachable before first use — deliberately rejected for scope discipline; documented as an accepted gap in the ADR instead.
- A new Prometheus metric or other observability surface for unload/reload success/failure beyond the WARN/INFO log lines required by FR11 — deliberately rejected for scope discipline (this is a lower-traffic, operator-configured path, unlike ADR-0013's per-request hot path); documented as a deliberate, named scope decision in the ADR.
- A per-backend configurable timeout — FR18 mandates a single shared constant bump, not per-backend tuning.

## Acceptance criteria
1. With `UPSTREAM_UNIT_NAME` unset, empty, or whitespace-only, `openaiBackend.Unloader()` returns a value that is `== nil` when compared against the `yield.Unloader` interface type — extending/verifying the EXISTING tests `TestOpenAIBackendUnloaderIsTrueNilInterface` and `TestOpenAIBackendUnloaderDoesNotTriggerDoUnload` in `internal/backend/openai_backend_test.go` (not new duplicate tests), using `Controller.SetMode(yield.ModeForceYield)` as the trigger mechanism — never the unexported `applyLocked` method.
2. With `UPSTREAM_UNIT_NAME` unset, `yield.go`'s nil-guard skips calling `doUnload` for the openai backend (no goroutine spawned, no panic) — verified via the existing test(s) in AC1.
3. With `UPSTREAM_UNIT_NAME` set to a non-empty value, `openaiBackend.Unloader()` returns a non-nil `yield.Unloader`.
4. With `UPSTREAM_UNIT_NAME` set, invoking the returned Unloader's `Unload` triggers exactly one `systemctl stop` invocation with the configured unit name, verified against a mocked/stubbed command runner (no real `systemctl` process spawned).
5. With `UPSTREAM_UNIT_NAME` set, invoking the returned Unloader's `Reload` triggers exactly one `systemctl start` invocation with the configured unit name, verified against the same mocked/stubbed command runner.
6. A test simulates the `systemctl stop` call failing (non-zero exit / error) and asserts the failure is returned as a real error, logged at WARN by `yield.go`'s shared `doUnload` logging, and does not panic or crash the calling goroutine.
7. A test simulates the `systemctl start` call failing analogously for `Reload`/`doReload`, asserting the same WARN-level logging behavior and no panic.
8. A test asserts that concurrent `Unload` and `Reload` calls for the same unit never execute simultaneously (e.g. by asserting serialized command execution order under a mutex-guarded critical section).
9. At least one test constructs the openai backend via the real `newOpenAIBackend(cfg)` factory function with `UPSTREAM_UNIT_NAME` set, then exercises `Unload` and `Reload` through the object that factory actually built — not a hand-built internal Unloader struct — so a forgotten or nil command-runner field wired into the real factory would be caught by the test.
10. No test in the affected packages spawns a real systemd process, requires a running vLLM instance, or calls a real `/sleep` or `/wake_up` HTTP endpoint.
11. `internal/config/config_test.go` contains passing tests for `UPSTREAM_UNIT_NAME` unset (empty string/default), whitespace-only, and set (non-empty value, including a value with surrounding whitespace that trims to a valid unit name) states.
12. `go test ./...` passes with no new failing packages/tests compared to `main`, and the pre-existing `internal/admin` failure remains the only failure, unchanged.
13. `go vet ./...` reports no new findings compared to `main`.
14. `docs/adr/` contains a new one-page ADR for this change covering: the stop/start decision and why `systemctl restart` was rejected (VRAM recontention after eager reload — functionally the same failure as the already-rejected "cancel-but-leave-loaded" alternative, just delayed); at least one rejected alternative including vLLM's native `/sleep`+`/wake_up` API with the vllm-project/vllm#20627 rationale; explicit references to ADR-0003 and ADR-0004; the recommended scoped sudoers/polkit grant (stop/start only, on the one configured unit, never a wildcard); the accepted connection-error window during stop/start as a named, documented cost; and the deliberately-rejected Prometheus metric surface and startup preflight check as named, deliberate scope cuts, not silent omissions.
15. The README config table lists `UPSTREAM_UNIT_NAME` with a description and its disabled-by-default state.
16. `deploy/broker.service` includes `UPSTREAM_UNIT_NAME` (unset/empty), consistent with the deployed default of leaving the Unloader a no-op.
17. The config-flags doc referenced by broker-change-control documents `UPSTREAM_UNIT_NAME` alongside the repo's other env vars.
18. Code review confirms no code path in the changed files can produce a typed-nil `yield.Unloader` value under any configuration state (empty string, whitespace-only string, valid unit name).
19. `internal/backend/backend.go`'s `Unloader()` interface doc comment is updated so it no longer implies every backend always returns nil, while still requiring that nil-when-applicable be a literal nil (never a typed-nil concrete pointer).
20. `ollama.Client`'s new `Reload` implementation is covered by a test asserting it returns `nil` immediately, executing no command and making no network call.
