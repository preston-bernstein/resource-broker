# Plan: vLLM/OpenAI-backend VRAM-yield Unloader

## Redesign note (supersedes the original single-`Unload`, `systemctl restart` draft)

Adversarial spec review found the original mechanism broken: `systemctl restart <unit>` is stop+start bundled as one systemd job, and a `vllm serve` unit eagerly reloads its model and re-claims GPU memory at process startup — independent of whether gaming contention is still active. The original plan would have freed VRAM for a brief gap and then automatically re-occupied it for the rest of the gaming session: the exact "cancel-but-leave-loaded" failure mode ADR-0003 already rejected, just delayed a few seconds instead of never happening. This redesign replaces `restart` with **symmetric stop/start**, driven by two distinct calls the yield Controller already has two distinct transition points for (yield-start, yield-clear) — mirroring Ollama's real behavior, where unload is forced on yield-start but reload is left lazy until serving actually resumes.

## Approach
Give `openaiBackend` an optional `yield.Unloader` implementation backed by a new `systemdUnitController` that:
- on **yield-start** (`Unload`), runs `systemctl stop <UPSTREAM_UNIT_NAME>` — frees VRAM immediately and leaves the unit down for the entire contention window, no eager reload;
- on **yield-clear** (`Reload`), runs `systemctl start <UPSTREAM_UNIT_NAME>` — brings vLLM back up, which reloads the model on its own startup path.

This requires widening `yield.Unloader` (currently `Unload(ctx) error` only) with a second method, `Reload(ctx context.Context) error`, and calling it from `applyLocked`'s `eff == false` branch, symmetric to how `Unload` is already called via `go c.doUnload()` in the `eff == true` branch. `ollamaBackend`'s existing `*ollama.Client` unloader gets a no-op `Reload` (Ollama's reload is implicit — the next `/api/generate` call lazily reloads whatever `keep_alive` unloaded — so there is nothing to actively trigger).

The command-runner seam is narrowed from the original design's fully-generic `func(ctx, name string, args ...string) error` (flagged by design review as inviting future misuse — a primitive that can run arbitrary binaries with arbitrary args when only one operation is ever needed) to `func(ctx context.Context, verb string) error`, scoped to exactly "run `systemctl <verb> <this configured unit>`." The production implementation always calls `exec.CommandContext(ctx, "systemctl", verb, unit)`; tests substitute a stub that asserts on `verb` ("stop"/"start") without ever spawning a real process.

The type is renamed from the original draft's `systemctlUnloader` to `systemdUnitController` since it now performs two distinct operations, not one restart, and gains an internal `sync.Mutex` so `Unload` and `Reload` for the same instance can never execute concurrently — this matters because `yield.go`'s debounce is asymmetric (entering yield is debounced via `confirmPolls`; clearing is never debounced, by design, per `yield.go`'s own doc comment on `NewWithConfirm`), so a rapid yield-start/yield-clear flap can spawn a `doUnload` goroutine and a `doReload` goroutine close together. The mutex prevents `systemctl start` racing `systemctl stop` against the same unit; it does not add debouncing (out of scope — see Risk areas).

The typed-nil hazard from the original plan is preserved unchanged: `openaiBackend` still stores its `yield.Unloader` in a struct field of the *interface* type itself, so an empty (or whitespace-only, after trimming) `UPSTREAM_UNIT_NAME` leaves that field at its zero value — a true nil interface — and `Unloader()` just returns the field. No concrete-typed pointer variable exists anywhere on the empty path that could get boxed into the interface.

## Architecture
```
config.Load()                          openaiBackend
  UPSTREAM_UNIT_NAME=""    ────┐          .unloader yield.Unloader (interface-typed field)
  (trimmed before the          │
   empty-check, so             ├─ empty  → field stays zero value → Unloader() returns literal nil
   whitespace-only == unset)   │
                                └─ set    → field = newSystemdUnitController("vllm")
  UPSTREAM_UNIT_NAME="vllm"                    = &systemdUnitController{unit:"vllm", run: <exec.CommandContext closure>}
                                                          │
yield.Controller.applyLocked()  (extended, not rewritten)│
                                                          │
  eff == true  (yield-start)                             │
    if c.unloader != nil { go c.doUnload() } ── Unload(ctx) ──┐
                                                               ├─ mu.Lock()
  eff == false (yield-clear)                                  │  run(ctx, "stop")  → exec.CommandContext(ctx,"systemctl","stop","vllm")
    if c.unloader != nil { go c.doReload() } ── Reload(ctx) ──┤
                                                               ├─ mu.Lock()
                                                               │  run(ctx, "start") → exec.CommandContext(ctx,"systemctl","start","vllm")
                                                               └─ mu.Unlock() (each call; never both held at once)
                          │                                              │
              success → nil                                  failure → wrapped error
                          │                                              │
     doUnload:  slog.Info "vram unload requested"    doUnload:  slog.Warn "vram unload failed"
     doReload:  slog.Info "vram reload requested"    doReload:  slog.Warn "vram reload failed"
```
`Backend` interface and `cmd/broker/main.go`'s wiring (`be.Unloader()` already flows generically into `yield.NewWithConfirm`) are unchanged — the widened `Unloader` interface flows through the same plumbing.

## API / interface contract
- New env var `UPSTREAM_UNIT_NAME` (string, default unset/empty). Whitespace-only values are trimmed and treated identically to unset/empty (fixed at the `config.Load()` parse boundary, not scattered across call sites). No CLI flags exist in this repo (env-only, per `broker-config-and-flags`).
- `yield.Unloader` widens from one method to two:
  ```go
  type Unloader interface {
      Unload(ctx context.Context) error
      Reload(ctx context.Context) error
  }
  ```
  Both are optional-by-nil at the `Backend.Unloader()` boundary (a backend with no VRAM control returns a true nil interface; neither method is ever called on a nil `Controller.unloader`).
- Effective behavior contract:
  - unset/empty/whitespace-only → `openaiBackend.Unloader()` returns `nil` (interface) → yield transitions never call `Unload`/`Reload` for this backend; current behavior preserved exactly.
  - non-empty → `openaiBackend.Unloader()` returns a `*systemdUnitController` →
    - on every yield-start transition, `Unload(ctx)` runs `systemctl stop <unit>`;
    - on every yield-clear transition, `Reload(ctx)` runs `systemctl start <unit>`;
    - each call is bound by a shared `unloadReloadTimeout` constant in `yield.go` (widened from the previous hardcoded 10s — sized for Ollama's near-instant HTTP unload call — to 30s, to give a `systemctl stop`/`start` CLI invocation room to return in the common case). This is a single shared constant, not a per-backend configurable knob (that would be gold-plating beyond what's specified). It is a **client-side give-up bound only**: `systemctl` talks to PID 1 over D-Bus, so killing the `exec.CommandContext` process at the timeout does **not** cancel the systemd job already queued — the stop/start may complete (or keep failing) asynchronously after `doUnload`/`doReload` has already logged and returned. Documented both as a code comment on the constant and as an accepted cost in the ADR.
  - failure (non-zero exit / exec error) on either verb → wrapped error (`fmt.Errorf("systemctl %s %s: %w", verb, unit, err)`); `yield.go`'s existing WARN-on-failure/INFO-on-success logging pattern applies symmetrically to both `doUnload` ("vram unload failed"/"vram unload requested") and the new `doReload` ("vram reload failed"/"vram reload requested"); no panic, no crash (backstopped by each method's own `recover()`, mirroring `doUnload`'s existing one).
  - `Unload` and `Reload` on the same `*systemdUnitController` never run concurrently (internal mutex); this bounds only same-instance races, it is not a substitute for the confirm-debounce that already governs how fast yield-start can re-trigger.

## Integration points
**Ordering constraint**: the ADR (`docs/adr/0014-...`) must land before-or-with the code change, not as an independently parallelizable step — this repo's own change-control gate requires the ADR to exist at the same time as (or ahead of) the behavior it governs, not trail it. Do not schedule the ADR and the `yield.go`/`openai_backend.go` changes as independent, unordered work items.

- `docs/adr/0014-vllm-yield-symmetric-stop-start.md` — new ADR (next available number after 0013), matching the tone/format of ADR-0003 and ADR-0013 (a short accepted-decision doc, not a template with empty sections). Must cover:
  - the decision: `systemctl stop`/`systemctl start` on yield-start/yield-clear respectively, referencing ADR-0003 (the hard-yield invariant this completes for the openai backend) and ADR-0004 (GPU scheduling policy this sits under);
  - the rejected mechanism and why: `systemctl restart` bundles stop+start into one job, so a unit that eagerly reloads on startup (as `vllm serve` does) re-claims GPU memory almost immediately regardless of whether contention is still active — recreating the "cancel-but-leave-loaded" failure mode ADR-0003 already rejected, merely delayed;
  - the rejected alternative from the original draft, vLLM's `/sleep`+`/wake_up` API, citing `vllm-project/vllm#20627` (still rejected under the redesign, for the same reasons as before — the mandated mechanism is a systemd stop/start, not an in-process sleep API);
  - **security scope**: an explicit recommendation that the sudoers/polkit rule granted to the broker's service account be **unit-specific** — e.g. permitting exactly `systemctl stop <exact-unit>` and `systemctl start <exact-unit>`, never a wildcard grant such as `systemctl restart *` or `systemctl * vllm*`. State the concrete risk: if the sudoers rule is ever misconfigured as a wildcard, an operator-set `UPSTREAM_UNIT_NAME` value effectively controls what the broker's service account can stop/start on the host — a privilege-escalation surface introduced by this feature that host-level config discipline, not application code, must close;
  - **accepted costs**, named explicitly rather than omitted: (a) consumer requests during the stopped/restarting window fail with connection errors handled by existing retry/backoff — no new coordination is being built for this; (b) no active startup preflight check validates the configured unit exists or that the sudoers rule is correctly scoped — misconfiguration surfaces only on the first real yield event, via the WARN log line; (c) no new Prometheus metric/observability surface is added for unload/reload outcomes — a deliberate scope decision for this lower-traffic, operator-configured path, explicitly noting the tension with ADR-0013's precedent (which *did* add an observability surface for its per-request hot-path embed lane) rather than pretending the asymmetry doesn't exist;
  - **rejected, named explicitly**: a new Prometheus metric for unload/reload outcomes; an active startup-time preflight check (`systemctl show <unit>`); full systemd-unit-name syntax validation beyond whitespace-trimming.

  `strings` is already imported. `getenv`'s own set-but-empty-counts-as-unset semantics handles the plain-empty case; `TrimSpace` additionally collapses whitespace-only values (`"   "`) to `""` *before* any empty-check downstream sees them, so `newOpenAIBackend` never has to special-case whitespace itself — this is the config-parse boundary, the same place every other env var on this struct gets normalized.

## Technology choices
- `os/exec`'s `CommandContext` — unchanged from the original draft; already used elsewhere in this repo (`cmd/broker/main_test.go`) for subprocess control with context cancellation. Both `Unload` and `Reload` use it identically, differing only in the `verb` argument.
- A narrowed function-value field (`run func(ctx context.Context, verb string) error`), not the original's fully-generic `func(ctx, name string, args ...string) error` — the narrower seam can only ever run `systemctl <stop|start> <the configured unit>`, closing off the "invites future misuse" concern design review raised about a primitive that can run arbitrary binaries with arbitrary args when only one operation is ever needed. Still a func field, not a new `CommandRunner` interface — no such interface exists anywhere in this codebase, and a func field remains the smallest thing that satisfies "substitutable with a stub" for tests.
- `sync.Mutex` on `systemdUnitController`, not a channel or a `sync/atomic` flag — the smallest primitive that serializes two methods (`Unload`, `Reload`) on the same receiver; matches this repo's existing mutex-for-simple-mutual-exclusion style (e.g. `yield.Controller.mu` itself).
- A single shared `unloadReloadTimeout` constant in `yield.go`, not a per-backend configurable knob — the requirements explicitly call a configurable timeout gold-plating beyond scope; one reasoned value (30s, up from the Ollama-sized 10s) covers both `doUnload` and `doReload` for every `Unloader` implementation, present and future.

## Risk areas
- **`systemctl restart` was the actual bug this redesign fixes, not a hypothetical** — the original draft's mechanism would have silently re-occupied VRAM mid-contention. The regression test most likely to catch a reintroduction of this bug is `TestSystemdUnitControllerUnloadRunsStop`/`...ReloadRunsStart` asserting the literal verb string passed to `run`; a future "simplification" back to a single `restart` call must fail these tests immediately.
- **Typed-nil correctness under refactor** (carried over from the original plan, still applicable): the interface-typed-field pattern is easy to accidentally break — e.g. a future edit introducing `var u *systemdUnitController; return u` from `Unloader()` would reintroduce the exact typed-nil bug ADR-0003/ADR-0014 guard against. `TestOpenAIBackendUnloaderIsTrueNilInterface` is the durable regression guard.
- **Sudoers/polkit misconfiguration as a privilege-escalation surface**: this is genuinely new risk surface this feature introduces (not present when the openai backend had no `Unloader` at all) — if the host-level sudoers/polkit rule is ever set broader than the exact unit (e.g. a wildcard), `UPSTREAM_UNIT_NAME` becomes an attacker- or misconfiguration-controlled lever over what the broker's service account can stop/start on the host. Out-of-repo host configuration (explicitly out of scope for code), but the ADR must recommend the unit-specific scoping explicitly rather than leaving it to operator discretion silently.
- **Widened timeout is a give-up bound, not a completion guarantee**: because `systemctl` hands the job to PID 1 over D-Bus, `doUnload`/`doReload` timing out and logging a WARN does not mean the stop/start didn't happen — it may complete moments later, unobserved. This is a real gap in what the WARN log actually proves, worth remembering when reading logs during an incident: "vram unload failed" at the 30s mark means "we gave up waiting," not "the unit is still up."
- **No debounce on the reload side, by design**: `yield.go`'s existing `debounceLocked` only debounces entry into yield (`confirmPolls`); clearing is intentionally instant. Combined with `doUnload`/`doReload` each running in their own goroutine, a fast contention flap (yield-start immediately followed by yield-clear) can fire `systemctl stop` and `systemctl start` for the same unit in quick succession. The new mutex prevents them from racing each other's `exec.CommandContext` call, but does not prevent the flap itself — this matches the existing, un-debounced clear-side behavior for every other `Unloader` (including Ollama's), so it is not a new problem this feature introduces, just one now visible on a slower, heavier resource (a full process stop/start vs. an HTTP call).
- **`internal/yield/yield_test.go` compiles against the widened interface only if every existing test double is updated** — this is a mechanical but easy-to-miss step (four structs need a `Reload` method added or the whole `yield` package fails to build), called out explicitly in Integration points above so it isn't discovered only at `go test ./...` time during implementation.
- **Restart-vs-stop/start latency during yield is now longer, not shorter, on the serve-resumption side**: unlike Ollama's `keep_alive=0` unload (a lightweight API call), `systemctl stop` tears down the whole vLLM process and `systemctl start` relaunches it — the resumption path pays a full process cold-start (weights load, CUDA init) after every yield-clear, not just the first one. This is inherent to the mandated mechanism, not this plan's choice, but is worth the ADR stating explicitly as an accepted cost (folded into accepted-cost (a) above: consumer requests during this window rely on existing retry/backoff, no new coordination is being built).
