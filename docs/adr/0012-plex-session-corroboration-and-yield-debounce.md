# Plex session corroboration and yield-entry debounce

**Status: accepted; implemented in `internal/plex/`, `internal/detect/detect.go`, `internal/yield/yield.go`, `internal/config/config.go`, wired in `cmd/broker/main.go`.**

Detection (ported verbatim from the Bash V3 daemon, see ADR-0001) matches "Plex Transcoder" by process name alone and yields on the first poll that sees it. Two false-positive sources were observed live: (1) Plex runs its own transcoder binary for background maintenance — Skip Intro/Credits detection, chapter-thumbnail generation, loudness analysis — on a server-scheduled cadence, completely independent of anyone watching anything; (2) a single-poll process-match blip (e.g. a game launcher's background housekeeping subprocess transiently matching a gaming regex) is not sustained gameplay. Both false-positive classes make the Broker yield the GPU — refusing all inference — for no real contention, hurting the Broker's actual purpose without protecting anything.

**Decision**: two independent, additive changes, both fail-safe toward yielding (never fail-safe toward serving — the yield-to-gaming/Plex law, ADR-0003/0004, is untouched):

1. **Plex session corroboration** (`internal/plex.Client`): when `PLEX_TOKEN` is set, a "Plex Transcoder" process match is corroborated against Plex's own `/status/sessions` endpoint (scoped to real "Now Playing" activity, unlike a process-name match) before being reported as contention. A `PlexSessionChecker` error (Plex unreachable) is treated as **fail-safe toward yielding** — an unreachable Plex API must never silently hide real contention — so an error still yields. No `PLEX_TOKEN` configured: the pre-existing process-match-only behavior is unchanged (fail-closed default, opt-in corroboration).
2. **Yield-entry debounce** (`YieldConfirmPolls`, `yield.Controller.debounceLocked`): the Controller requires `BROKER_YIELD_CONFIRM_POLLS` (default 2) consecutive same-reason detections before reporting contention upward and entering yield. A reason change (e.g. `gaming-heroic` then `gaming-wine`) resets the count rather than carrying it over — flapping between two reasons must not accumulate confirmation for either. **Clearing contention is never debounced**: it takes effect on the very next poll, since faster recovery only benefits inference and never risks starving gaming/Plex.

**Why now**: both false-positive classes were observed to cost inference availability — Plex's own background jobs and launcher blips are common enough on this desktop (Tdarr, game launchers, and Plex's maintenance jobs all run routinely) that spurious yields were a measurable tax on Consumer availability, motivating the 2026-07-15 research pass behind both fixes.

**Rejected alternatives**:
- *Debouncing Plex detection alone, not gaming*: gaming launcher blips are the same failure shape (single-poll match, not sustained), so scoping debounce to Plex only would leave the gaming half of the bug unfixed.
- *A fixed sleep/re-check inside `Detect()` itself*: `Detect()` is a stateless point-in-time snapshot (`internal/detect`), used directly by tests with a fake `Lister`; making it stateful (remembering poll history) would break that contract and entangle two different packages' responsibilities. Debounce state belongs in the Controller, which already owns poll-to-poll state (`lastPoll`, `autoContended`).
- *Debouncing the clear path too (symmetric hysteresis)*: rejected — a delayed clear only costs inference time it would have gotten back anyway, but a delayed yield-entry risks letting inference run a beat longer while a game/transcode is genuinely starting, which is the one outcome (ADR-0003) this project exists to prevent. Confirmation requirements apply to entry only.
- *A GPU-utilization threshold instead of a session check*: rejected for the same reason ADR/detect's V1/V2 attempts were abandoned (circularity — the Broker's own inference load pollutes the signal it's trying to read); Plex's session API is external ground truth, not a derived GPU metric.

**Config**: `BROKER_YIELD_CONFIRM_POLLS` (default `2`), `PLEX_URL` (default `http://localhost:32400`), `PLEX_TOKEN` (default unset — corroboration disabled). See README's config table and `deploy/broker.service` (Plex lines shipped commented out pending a token; yield-confirm-polls active with the code default).

**Observability**: `cmd/broker/main.go` logs `plex session corroboration enabled` at startup when `PLEX_TOKEN` is set, and `yield_confirm_polls` rides the existing `broker up` startup log line. No new Prometheus metric was added — debounced-but-not-yet-confirmed contention is not distinguishable from "no contention" in `/metrics` today; if that gap matters operationally, add a counter as a follow-up, not blocking this ADR.
