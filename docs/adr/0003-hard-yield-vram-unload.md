# Yield is hard: cancel in-flight and force Ollama to unload VRAM

When contention appears (a game or Plex transcode is detected), gaming has absolute priority, so the Broker yields hard: it immediately cancels the in-flight upstream Ollama call **and** forces Ollama to unload the model from VRAM (`keep_alive=0` / stop). Cancelling the request alone is insufficient — Ollama keeps the model resident in VRAM, which keeps starving the game. The interrupted in-flight request returns `503` for batch callers (fashion-monitor `PENDING` absorbs it) or a truncated stream plus error for interactive callers (client retries). We rejected graceful drain (letting a 70b generation finish could stall the game for minutes, violating "gaming absolute") and cancel-but-leave-loaded (VRAM stays occupied, game still contends). The cost is a model reload of a few seconds when the queue resumes after contention clears — an acceptable trade for a clean GPU during play.
