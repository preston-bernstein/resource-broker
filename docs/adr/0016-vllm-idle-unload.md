# Idle-unload for openai-compatible (vLLM) backend instances

**Status: accepted; implemented in `internal/yield/yield.go` (`Controller.idleTimeouts`/`lastDispatch`/`inFlight`/`idleUnloaded`/`origToFiltered`, `ConfigureIdle`, `TrackActivity`, `checkIdleLocked`, `IdleSummary`, the `unloadTrigger` type on `doUnload`/`doReload`), `internal/backend/activity.go` (new file: `activityBackend`, `WithActivityTracking`), `internal/config/config.go` (`Config.UpstreamIdleTimeout`, `RouteBackend.IdleTimeout`, `UPSTREAM_IDLE_TIMEOUT` / `BROKER_ROUTE_<N>_IDLE_TIMEOUT`), `internal/admin/admin.go` (`idleStatus` param on `Mux`), `cmd/broker/main.go` (`buildBroker`, corrected routes-branch construction order).**

Ollama frees VRAM on its own after `OLLAMA_KEEP_ALIVE` of inactivity. The openai-compatible backend (vLLM) has no equivalent: once ADR-0014's `systemctl start` brings a unit up, it stays resident indefinitely, and the only thing that has ever freed it is a real gaming/Plex Contention event (ADR-0003/ADR-0014). On a single ~16GB GPU shared between Ollama and vLLM, this asymmetry means whichever backend was used more recently silently evicts the other from VRAM for as long as the box runs, with no Contention event required to trigger it and none able to reverse it — discovered live during a benchmarking sweep that alternated between the two and kept failing to get both loaded at once. This ADR closes that gap: every configured openai-compatible instance (default backend or a `BROKER_ROUTE_<N>` route) that already has a `yield.Unloader` wired can now be given its own idle duration, after which it unloads itself the same way Contention already unloads it, and reloads itself on its next real request. Idle-unload is a second, independent trigger into ADR-0014's existing per-instance action chain — never a new controller, timer goroutine, or unload mechanism — and it must never weaken ADR-0003/ADR-0004's absolute gaming-preemption invariant or ADR-0015's per-instance independence.

**Decision — same goroutine, extended, not a second poller.** `Controller.refresh()` already runs once per `DetectInterval` tick, inside a single `c.mu`-locked critical section, in the one goroutine `Run` owns. This feature adds exactly one line to that function: `c.checkIdleLocked()`, called immediately after the existing `c.applyLocked()`, still under the same lock. Running Idle strictly after Contention in the same tick means `checkIdleLocked` always observes the post-transition `c.effective` value for that tick — there is no second goroutine that could read stale Contention state and race a decision against it, and no new synchronization primitive is needed to keep the two triggers ordered correctly relative to each other. The Contention transition's own `Unload`/`Reload` calls are *spawned* as goroutines inside `applyLocked`, not run synchronously, so the handful of extra atomic reads `checkIdleLocked` performs afterward adds no observable latency to a Contention-triggered Yield transition — the property the plan's non-functional requirement calls out explicitly ("never delay... a Contention-triggered Yield transition").

Per-instance idle state — `idleTimeouts []time.Duration`, `lastDispatch []atomic.Int64`, `inFlight []atomic.Int32`, `idleUnloaded []atomic.Bool` — lives on `Controller` itself, index-aligned with the existing post-nil-filter `unloaders`/`labels`/`actionDone` slices, not on `Router` or `openaiBackend`. Reads and writes to these four fields use `sync/atomic`'s typed wrappers rather than `c.mu`, deliberately: the per-request hot path (`TrackActivity`'s common case, every proxied request to an idle-configured instance) must never contend on the same lock that guards Contention's own state. `checkIdleLocked` reads them while already holding `c.mu` for the Contention check anyway, so no data race exists per Go's atomics happens-before rules — but it is a genuinely less obvious concurrency shape than "everything behind one mutex," and a future edit that turns `lastDispatch` back into a plain field for convenience would silently reintroduce a race.

Request-side tracking is a decorator, not a change to `Router`, `Gate`, or the Job worker: `internal/backend/activity.go`'s `WithActivityTracking(b Backend, ctrl *yield.Controller, origIdx int) Backend` calls `b.Proxy()` exactly once at wrap time to obtain the real `http.Handler`, wraps it exactly once via `ctrl.TrackActivity(origIdx, realHandler)`, and returns a `Backend` whose own `Proxy()` just returns that already-built handler on every call — never rebuilt per request. On every dispatch the wrapped handler increments `inFlight[post]`, sets `lastDispatch[post]=now`, and — if `idleUnloaded[post]` CAS-transitions true→false — calls `startAction(post)` and spawns `doReload(post, ..., triggerIdle)` before calling through to the real proxy. The `inFlight` decrement is registered via `defer` immediately after the increment, so it fires even if the proxied call panics; an un-decremented counter would permanently misrepresent that instance's in-flight state to `checkIdleLocked`.

**Decision — `origToFiltered`, and the direction matters.** `NewWithConfirmMulti` already filters out any `nil` `Unloader` (an instance with no `_UNIT_NAME`) when it builds the post-filter `unloaders`/`labels`/`actionDone` slices, so those slices are indexed in "post-filter" space while every caller in `cmd/broker/main.go` (`ConfigureIdle`, `TrackActivity`) naturally thinks in "orig" space — the same numbering `unloaders := append([]yield.Unloader{be.Unloader()}, routeUnloaders...)` already establishes: orig-index 0 is the default backend, orig-index `i+1` is `cfg.Routes[i]`. `origToFiltered []int`, sized to `len(unloaders)` as passed into the constructor, is built once in the same filter loop, mapping **ORIG → POST-FILTER**: for orig index `i`, `origToFiltered[i] = -1` if `unloaders[i]` was filtered out, otherwise that entry's position in the filtered slice. This is the direction `ConfigureIdle`/`TrackActivity` actually need, because both receive orig-indexed input from `main.go` and must translate it into the correct slot in `idleTimeouts`/`lastDispatch`/`inFlight`/`idleUnloaded`, which are post-filter-indexed. An earlier draft of this design had the mapping built in the opposite direction (POST-FILTER → ORIG), which is the wrong direction for either caller and would have required an O(n) scan (or a second map) at every `ConfigureIdle`/`TrackActivity` call just to invert it back. Both `ConfigureIdle` and `TrackActivity` look up `post := c.origToFiltered[origIdx]` and, if `post == -1` for a nonzero idle timeout, `panic` with a message identifying the orig index rather than silently skipping or indexing out of bounds — a nonzero idle timeout on an instance with no Unloader is a construction-time invariant violation that `config.Load()`'s own validation (a route or the default backend cannot set an idle duration without a `_UNIT_NAME`) should already have prevented; reaching this panic means that validation was bypassed, and failing loudly here is preferable to a silent no-op or an out-of-bounds write.

**Decision — the FR11/AC7 two-`Unload`-call idempotent carve-out.** Idle and Contention both reach VRAM control exclusively through `startAction(i)`/`actionDone[i]` — ADR-0014's predecessor-completion chain, unmodified, now with a third caller. Two sequences matter:
1. Idle is about to fire the same tick Contention begins: `checkIdleLocked` runs strictly after `applyLocked` in the same `refresh()` call, so it always observes `c.effective == true` already and skips that instance outright. Only Contention's `Unload` fires — zero duplicate calls.
2. Idle already fired in an earlier tick (`idleUnloaded[i] == true`), and Contention begins later: `applyLocked`'s existing all-instance `Unload` loop fires again for instance `i` **unconditionally** — it does not know or care about Idle's per-instance bookkeeping, by design, because Contention's response must stay dead simple and instance-idle-agnostic (ADR-0004's absolute-priority invariant: gaming/Plex always wins, full stop, with no dependency on any other trigger's state). The result is a second `systemctl stop` against an already-stopped unit. This is accepted as idempotent-and-harmless, not treated as a bug to design around: it is strictly ordered after Idle's own `Unload` by the shared `actionDone[i]` chain, so it is never a *conflicting* pair (no out-of-order `Unload`/`Reload` race) — the one property FR11/AC7 actually require. Making Contention's unload loop Idle-aware to suppress the redundant call was considered and rejected as unwarranted complexity in the one code path that must never get more complicated: Contention's response has to remain correct even if every other piece of bookkeeping in the process is stale or wrong.

**Decision — fire-and-forget wake, an accepted cost restated for a new trigger.** `TrackActivity`'s CAS-won wake branch spawns `doReload` and calls through to the real proxy immediately, without waiting for the reload to complete. The waking request — and any other request arriving during vLLM's cold-start window that follows — will very likely see connection errors against the still-down upstream, exactly as a Contention-triggered wake already produces. This is not a new design element: it mirrors ADR-0014's own "accepted cost — connection-error window" framing verbatim, handled by the same caller retry/backoff Consumers already build against Contention's identical behavior. It is written down again here, rather than assumed inherited silently, because Idle-unload is a new source of that same window and a future reader of this ADR should not have to cross-reference ADR-0014 to learn that the cost exists.

**Decision — `WithActivityTracking` must return a pointer, not a value.** `activityBackend` embeds `Backend` (an interface) and stores a `proxy http.Handler` field whose concrete value, per `ctrl.TrackActivity`'s own implementation, is a closure. Go func values are not comparable — comparing two of them panics (`runtime error: comparing uncomparable type`) rather than returning `false`. `Router.RoutingSummary()` (`internal/backend/router.go`) uses `Backend` as part of a map key (`type key struct { backend Backend; lane string }`), which requires the map key's dynamic type to support `==` the moment two decorated backends are compared — something `RoutingSummary()` does on every call, and `/status` triggers on every poll. A bare `activityBackend` value satisfies `Backend` and would compile cleanly, but its dynamic type carries the uncomparable closure field, so the very first `/status` poll against a routing configuration with two or more idle-tracked instances would panic at the map-key comparison. A pointer type (`*activityBackend`) is always comparable regardless of what the pointed-to struct holds, so `WithActivityTracking` returns `&activityBackend{...}` unconditionally — never a value — and this must not be "simplified" back to a value type in a future edit.

**Rejected: vLLM's native `/sleep` + `/wake_up` API.** Rejected here for the same reason ADR-0014 already rejected it for Contention: the open, unresolved upstream bug vllm-project/vllm#20627 reports corrupted output on the OpenAI-compatible-server path after repeated sleep/wake cycles. ADR-0014's rejection was made against Contention's usage pattern — rare, gaming-session-triggered flaps. Idle-unload's expected fire frequency is materially higher: routine usage gaps during ordinary operation, much closer to the repeated-cycle pattern #20627 actually exercises. That makes this decision worth revisiting specifically for the Idle trigger once that bug closes upstream — `systemctl stop`/`start` remains the correct, and only, choice today, unchanged by this ADR.

**Rejected: a new Prometheus metric.** Idle-triggered `Unload`/`Reload` outcomes get no new metric or observability surface, same as Contention-triggered ones (ADR-0014's own precedent) — they get a `trigger` field (`"idle"` vs `"yield"`) added to the existing WARN/INFO log lines instead, so an operator can grep the two apart. This is a deliberate decision for a feature whose actual production risk — thrash from a workload with usage gaps landing near the configured idle timeout, each cycle paying full cold-start cost — is currently only log-visible; a per-instance idle-fire/idle-wake counter is a cheap, additive follow-up if that risk shows up in practice, not a redesign.

**Accepted cost — no hysteresis.** A workload whose usage gaps land near the configured `UPSTREAM_IDLE_TIMEOUT`/`BROKER_ROUTE_<N>_IDLE_TIMEOUT` will thrash, paying full unload/reload cold-start cost on every cycle. This is an operator-tuning consideration (configure the duration meaningfully larger than expected usage gaps), not a defect this feature's initial version addresses.

**Accepted cost — Job-path traffic does not reset the idle clock.** Only Synchronous requests proxied through `Router.resolve`/the default backend's `Proxy()` reset an instance's `lastDispatch`; the durable Job path (`job.Worker.Generate`, `Router.Generate`) is untouched. An instance driven exclusively by Job-path traffic, with no Synchronous traffic, can be idle-unloaded mid-Job. This matches the letter of the requirements as written and is a known, accepted limitation, not a defect.

**Accepted cost — a broker restart resets every instance's idle clock to "process start."** `lastDispatch` is in-memory only, matching Contention's own in-memory `Controller` state; no new persistence path was added for one non-critical timestamp. Worst case after a restart: VRAM sits loaded somewhat longer than the configured timeout before the clock catches up to real usage — never a correctness problem.

**Links**: ADR-0003 (hard-yield VRAM unload, the invariant Idle-unload reuses rather than replaces), ADR-0004 (GPU scheduling policy — gaming's absolute priority, which the FR11/AC7 carve-out exists specifically to preserve), ADR-0014 (vLLM symmetric stop/start — the `Unloader`/`actionDone` mechanism this feature adds a second event source into, and the rejected-`/sleep`+`/wake_up` rationale this ADR reapplies), ADR-0015 (per-model backend routing — the per-instance independent-chain guarantee, and the post-nil-filter index space `origToFiltered` maps into).
