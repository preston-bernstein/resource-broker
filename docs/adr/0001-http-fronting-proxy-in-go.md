# Arbitrate inference via an HTTP-fronting proxy, written in Go

The deployed V3 manager only governs commands run through its Bash batch-job wrapper. But the real inference consumers — the fashion-monitor pipeline, LightRAG, estate-scraper vision, open-webui chat — are long-running daemons that call Ollama's HTTP API (`:11434`) directly and will never invoke a CLI wrapper. So the Broker becomes an **HTTP-fronting proxy**: it listens on its own port(s), speaks Ollama's own API, applies queue/yield/priority, and forwards to real Ollama. Consumers integrate by simply repointing their Ollama host at the Broker — zero per-service code. The Broker is written in **Go** as a single static binary that folds the process-detection daemon and the proxy into one process, retiring the Bash V3 daemon and the competing Python/FastAPI Tier-3 direction; Go's goroutines map cleanly onto the concurrency-1 GPU gate, a live queue, cancellable upstream requests, and streaming passthrough, and it deploys as one systemd unit. The legacy file-based CLI batch wrapper remains only for true fire-and-forget command jobs, separate from the HTTP path.
