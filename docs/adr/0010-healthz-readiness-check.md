# `/healthz` becomes a real readiness check, not a hardcoded 200

**Status: accepted (2026-08-01 fleet observability audit); implemented 2026-08-01 in `internal/admin/admin.go` + `cmd/broker/main.go`.**

`GET /healthz` returned the literal bytes `"ok\n"` with 200, unconditionally, regardless of whether the Broker could actually do its job. Ollama could be completely dead — every proxied request 502ing — while `/healthz` stayed green and systemd showed the unit `active`. This is the same class of defect as a watchdog whose own probe always returns success: a health endpoint that structurally cannot fail is worse than no health endpoint, because it actively tells a monitor (Uptime Kuma, a future liveness probe) that everything is fine while it is not.

`/healthz` now runs a bounded (3s) `admin.HealthCheck` that answers three questions the process being "up" says nothing about: can the Broker reach the Ollama upstream (`ollama.Client.LoadedModels`, the same lightweight `GET /api/ps` call the VRAM-unload path already uses), can it read the durable Job store (`job.Store.HasQueued`), and is the contention-detection loop still actually polling (`yield.Controller.PollAge()`, new — tracks the timestamp of the last `refresh()`, compared against `3 * BROKER_DETECT_INTERVAL`). Any one failing returns `503` with a JSON body naming the failed dependency (`{"status":"unhealthy","error":"..."}`); all three passing returns `200 {"status":"ok"}`. `admin.Mux`'s `health` parameter is optional (nil preserves the old always-200 behavior) so tests that don't care about health can keep passing `nil` without constructing real dependencies.

The detector-staleness check exists because a wedged or never-started poll loop is a distinct failure mode from an unreachable Ollama: `internal/yield/yield.go`'s `Controller.Run` refreshes on a `time.Ticker`, and if that goroutine ever died silently, `broker_yielding` would simply stop updating — indistinguishable from "no contention" forever. `3×` the configured interval tolerates ordinary scheduling jitter without false-triggering on a still-healthy, just-slow poll.

We rejected making `/healthz` a pure liveness check (process is running, nothing else) — that is exactly the status quo this ADR replaces, and the audit's own framing (comparing it to the `alertmanager-ntfy` handler that always returned HTTP 200, making its own watchdog structurally unfireable) is the reason a check that can never fail is treated as a defect, not a simplification. We also rejected checking Ollama with a full inference round-trip (`/api/generate`) — that would itself consume the single GPU slot this Broker exists to arbitrate, so `/healthz` would compete with real inference traffic for the resource it's supposed to be monitoring; `/api/ps` is a metadata read that touches no GPU state.
