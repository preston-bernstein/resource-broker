# Per-model upstream backend routing via an indexed route table

**Status: accepted; implemented in `internal/backend/router.go` (new `Router` type), `internal/backend/backend.go` (`NewInstance`), `internal/yield/yield.go` (`Unloader`/`actionDone` generalized to slices, `NewMulti`/`NewWithConfirmMulti`), `internal/config/config.go` (`RouteBackend`, `Config.Routes`, `BROKER_ROUTE_<N>_*`), `internal/admin/admin.go` (`routingStatus` param on `Mux`), `cmd/broker/main.go` (`buildRoutes`, conditional Router wiring).**

`UPSTREAM_BACKEND` (ADR-0001 onward) is a single global switch: the whole broker points at one upstream, either real Ollama or one OpenAI-compatible server. A 2026-08-15 desktop inventory found that doesn't match how the broker is actually used — the Interactive and Batch lanes each carry mixed traffic: chat requests, vision requests (`qwen3-vl:30b`, `qwen2.5vl:7b`), and embedding requests (`bge-m3`, `nomic-embed-text`), all sharing the same two ports. A vLLM instance now runs on the same desktop GPU serving exactly one chat model, and vLLM cannot natively multiplex multiple distinct base models on one process/port the way Ollama does — each additional model needs its own vLLM process, and this desktop's single 17.1GB GPU (shared with gaming/Plex) has no headroom for more than one resident vLLM model at a time. The goal: let an operator route specific model names to a second upstream instance (vLLM or a second Ollama) while everything else keeps flowing to the default backend unchanged, without requiring full model parity between backends, and without weakening ADR-0003/ADR-0004's gaming-preemption invariant or ADR-0014's per-instance flap-ordering fix for any of the now-possibly-multiple configured instances.

**Decision: a routing table over the existing config idiom, not a second listening port.** `Config.Routes []RouteBackend` is parsed from indexed `BROKER_ROUTE_<N>_{MODELS,BACKEND,URL,API_KEY,UNIT_NAME,LANE}` env vars (`N` = 1..32, 16-route cap), the same all-scalar, `getenv`-based idiom `config.go` already uses everywhere else — no new config format (e.g. a `BROKER_ROUTES=...` JSON/YAML blob) smuggled inside one env var. A request's `model` field is peeked from the JSON body (size-capped, streaming `json.Decoder`, never a full read) and matched against the table; a match is proxied to that route's backend instance instead of the default. Unset/empty `BROKER_ROUTE_1_MODELS` disables routing entirely — `Config.Routes` stays nil, and `cmd/broker/main.go` never constructs a `Router` at all, wiring `defaultBackend.Proxy()` directly into both gates exactly as before this feature. This is the same empty-disables-it precedent `UPSTREAM_UNIT_NAME` already set.

**Rejected: a second listening port per alternate backend, mirroring the embed lane (ADR-0008).** The embed lane exists as its own port because it is a structurally different request shape (image embedding) with its own timeout and slot semantics (ADR-0013) — a genuinely separate lane, not an alternate implementation of the same lane. Per-model backend routing is the opposite case: the same Interactive/Batch request shapes, same queue/yield semantics, same client-facing API, just resolved to a different upstream URL for specific model names. Adding a new port per alternate backend would mean every Consumer needing per-model routing wiring changes on the client side (which port to call for which model) instead of the broker transparently resolving it — reintroducing exactly the per-service coordination burden ADR-0001 built this broker to eliminate.

**`yield.Controller` generalized from a scalar `Unloader` to a slice of them, one independent ordering chain per instance.** `unloader Unloader`/`actionDone chan struct{}` became `unloaders []Unloader`/`actionDone []chan struct{}`; `applyLocked` loops `for i := range c.unloaders { go c.doUnload(i, c.startAction(i)) }` (and the reload-symmetric case), so every configured backend instance gets its own independent ADR-0014 flap-ordering chain — a slow or permanently-erroring instance never blocks or reorders another instance's chain. `New`/`NewWithConfirm` (scalar) are kept unchanged as one-element wrappers around the new `NewMulti`/`NewWithConfirmMulti` constructors, so every pre-existing `internal/yield` test compiles and passes with zero edits. This was the highest-risk change in the plan — it touches the single most safety-critical file in the repo — and is proven by three new dedicated tests asserting both-instances-fire, per-instance order preservation across a flap, and that one instance's permanent error does not delay or reorder another's actions. `doUnload`/`doReload`'s WARN/INFO log lines now carry a per-instance label (unit name, URL, or `instance[i]` as a fallback) so an operator investigating a stuck instance can tell which one from the log alone — with N independent instances now unloading in isolation, an unlabeled log line stopped being enough.

**`config.Load()` validates same-physical-resource collisions across every configured instance, not just within the route table.** No two instances — the default backend and/or any route — may share a resolved `_UNIT_NAME` or URL; every model name may be routed by at most one rule; route indices must be contiguous starting at 1 (a gap fails loudly rather than silently truncating the table). This is a one-way door if missed: a config mistake mapping two routes to the same underlying systemd unit would ship clean — nothing fails locally — and only surface in production as two independent ADR-0014 ordering chains issuing `systemctl stop`/`start` against the same unit out of order, reintroducing exactly the race ADR-0014's fix exists to prevent. There is no runtime signal that would catch this after the fact, so it has to be caught at `Load()` time or not at all.

**`Router.Unloader()` returns a literal `nil` — a deliberate trade-off, not an oversight.** `Router` implements the full `Backend` interface (so it can be handed to the same three call sites — the Gates, the Job worker, `/healthz` — that accept any `Backend`), which means it technically has an `Unloader()` method to satisfy. But `Router` itself has no VRAM to free; unload responsibility for each configured instance is wired explicitly in `cmd/broker/main.go`'s `buildRoutes`, which builds the combined `unloaders []yield.Unloader` slice (default backend's unloader plus each route's, index-aligned, typed-nil-filtered at construction per ADR-0014's existing discipline) and hands it directly to `yield.NewWithConfirmMulti` — bypassing `Router.Unloader()` entirely. A narrower custom interface (splitting `Backend` so `Router` wouldn't need to implement `Unloader()` at all) was considered and rejected as unnecessary churn for a pre-ship decision: one polymorphic `Backend`-satisfying type simplifies the three call sites that need it, at the cost of one method whose meaning must be documented rather than implemented. This is recorded here explicitly so a future contributor treating `Router` as an ordinary `Backend` — in a new test, or a refactor — doesn't read the nil stub as a bug and "fix" it by wiring `Router.Unloader()` into the yield controller, which would silently drop every route's actual unload/reload behavior.

**`Reachable(ctx)` checks only the default backend.** This preserves existing `/healthz` semantics (ADR-0010): a single optional alternate route being down does not flip the whole broker unhealthy or trigger unwanted restarts/alerts for what is, by definition, a non-critical secondary path. `RoutingSummary()` — surfaced via `/status`'s `"routing"` key, present only when at least one route is configured, matching the existing `tdarrStatus`/`jobStatus` conditional-inclusion pattern in `admin.Mux` — gives an operator per-route visibility without conflating "one optional route is down" with "the broker itself is broken."

**Rejected scope — no startup preflight for route reachability or unit-name authorization.** Same rationale ADR-0014 already gave for the default backend's `UPSTREAM_UNIT_NAME`: an active `systemctl show <unit>` probe or a live reachability check at config-load time would add a startup-time dependency on `systemctl`/D-Bus/network for a path most deployments (no routes configured) never exercise. A misconfigured route surfaces on first use — a failed proxy call or a failed `systemctl stop`/`start`, logged clearly — not silently.

**Links**: ADR-0001 (HTTP-fronting proxy, the "no per-service code" principle this feature preserves), ADR-0003 (hard-yield VRAM unload, the invariant every configured instance must still honor), ADR-0004 (GPU scheduling policy, gaming's absolute priority that must hold across all instances, not just the default), ADR-0008 (image embedding lane, the precedent for a separate-port lane this feature deliberately did not follow), ADR-0014 (vLLM symmetric stop/start, the per-instance ordering guarantee this feature's `yield.Controller` generalization had to preserve exactly).
