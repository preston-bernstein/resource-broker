# Plan: OpenAI-Compatible Upstream Backend

## Approach
Most of the decoupling this feature needs already exists in the code: `queue.Gate` takes a plain `http.Handler` as its `next` (`internal/queue/gate.go`), and `job.Worker` already calls through a `Generator` interface (`internal/job/worker.go`), not a concrete `*ollama.Client`. So the real seam is narrower than "rewrite the proxy" — it's a single new `internal/backend` package exposing a small `Backend` interface (`Proxy() http.Handler`, `Generate(...)`, `Reachable(ctx) error`, `Unloader() Unloader`), with two implementations: `ollamaBackend` (a thin wrapper around the existing `proxy.New`/`ollama.Client`, unchanged byte-for-byte) and `openaiBackend` (a new `internal/openaicompat` package that translates Ollama-shaped chat/generate and embed requests to/from an OpenAI-compatible upstream). `cmd/broker/main.go` becomes the single call site that branches on `cfg.UpstreamBackend`; every downstream consumer (Gate, `job.Worker`, admin health composition, yield's `Unloader`) keeps calling the same interfaces it calls today. `internal/ollama`, `internal/proxy`, and `internal/job/worker.go` are not modified at all, which is what makes requirement 21 (byte-identical `ollama` behavior) trivially true rather than something to verify by inspection — see the "structural, not measured" note under Technology choices for how that claim is actually checked.

The package is named `internal/openaicompat`, not `internal/openai`: this broker's whole purpose is arbitrating a shared home GPU for self-hosted inference, never calling a real hosted OpenAI API, and "internal/openai" reads as exactly that — a risk of future misconfiguration in a shop that deliberately never calls cloud inference. The package implements the OpenAI-*compatible* wire protocol against a self-hosted upstream (the real target is vLLM); the name should say that unambiguously.

## Architecture
```
                         cfg.UpstreamBackend ("ollama" | "openai")
                                     |
                         internal/backend.New(cfg)
                                     |
                +--------------------+--------------------+
                |                                          |
        ollamaBackend                              openaiBackend
        (wraps proxy.New +                         (wraps openaicompat.NewHandler +
         ollama.Client, unchanged)                   openaicompat.Client, new)
                |                                          |
    Proxy()---->httputil.ReverseProxy          Proxy()---->openaicompat translating handler
    Generate()->ollama.Client.Generate         Generate()->openaicompat.Client.Generate (SSE)
    Reachable()->oc.LoadedModels               Reachable()->GET {UPSTREAM_URL}/v1/models
    Unloader()->oc (Unload/LoadedModels)       Unloader()->nil (FR-19, no VRAM control —
                |                                          see "typed-nil safety" below)
                +--------------------+--------------------+
                                     |
                  cmd/broker/main.go wires be.Proxy() into BOTH
                  sched.Gate(Interactive, ..., be.Proxy())
                  sched.Gate(Batch, ..., be.Proxy())
                  and be.Generate as job.NewWorker's Generator,
                  be.Reachable into the existing healthCheck closure,
                  be.Unloader() into yield.NewWithConfirm(detector, ..., ...)

Consumer --(Ollama wire API, unchanged)--> Gate --> be.Proxy() --> [Ollama | OpenAI-compat upstream]
Job worker --(Generator interface, unchanged)--> be.Generate --> [Ollama | OpenAI-compat upstream]
```
The embed lane (`proxy.NewEmbed`, `INFINITY_URL`) is wired identically today and after this change — it never touches `internal/backend` (FR-18, AC-12).

**Typed-nil safety for `openaiBackend.Unloader()`.** `yield.go`'s nil-guard (`if c.unloader != nil { go c.doUnload() }`, `internal/yield/yield.go:216`) only catches a true nil *interface* value — a typed nil (a nil pointer of some concrete type boxed into the `yield.Unloader` interface, e.g. from `var u *someConcreteType; return u`) is NOT caught by that check, and `doUnload()` would then be invoked on a nil receiver inside an unrecovered goroutine, panicking and crashing the entire broker process — at the exact moment real gaming/Plex contention is detected under `UPSTREAM_BACKEND=openai`. `openaiBackend.Unloader()` MUST be implemented as a direct, literal return of the interface type with no intermediate typed variable:
```go
func (b *openaiBackend) Unloader() yield.Unloader { return nil }
```
never anything that assigns a concrete (possibly-nil) pointer to a local variable first and returns that. See "Design decisions" and the `internal/yield/yield.go` entry under Integration points for the accompanying defensive `recover()`.

For the `openai` backend's Synchronous path, `openaicompat.NewHandler(base, apiKey)` is a plain `http.Handler` (not an `httputil.ReverseProxy`) that inspects `r.URL.Path` and the decoded request body's `stream` field:
- `/api/generate`, `/api/chat` with `stream:true` (or unset — Ollama's own default) → decode Ollama request → POST `{base}/v1/chat/completions` with `stream:true` (plus `stream_options:{include_usage:true}`, see API contract) → parse the upstream's SSE (`data: {...}` lines) chunk by chunk → write Ollama NDJSON lines, flushing after each write (mirrors `FlushInterval: -1`).
- `/api/generate`, `/api/chat` with `stream:false` → same upstream call, but the handler internally collects the full completion from the streamed (or non-streamed) upstream response and writes a **single** Ollama-shaped JSON object at the end — no NDJSON framing, matching Ollama's real `stream:false` contract for these endpoints.
- `/api/embed` → decode Ollama embed request → POST `{base}/v1/embeddings` → reshape the OpenAI response into Ollama's embed response shape → single JSON write (Ollama's own `/api/embed` is non-streaming today, so no behavior change here).
- any other path (including Ollama-only endpoints such as `/api/tags`, `/api/show`, `/api/ps`) → `404` with a JSON error body. This is a real, deliberate behavior difference from the `ollama` backend, which passes every path through transparently: under `UPSTREAM_BACKEND=openai`, only `/api/generate`, `/api/chat`, and `/api/embed` exist (documented scope limit — FR-6/FR-7, out of scope section).

**Mid-stream error handling.** The pre-response-body failure path (below) only covers errors before any bytes are written. Once NDJSON chunks have already been flushed to the client, a clean HTTP status change is impossible — headers and body have already started. The handler mirrors Ollama's own convention for this exact situation (see `ollama.Client.Generate`'s in-band `chunk.Error` check): if the upstream sends an SSE error event, an `{"error":{...}}` payload, or a malformed/incomplete stream after chunks have already been forwarded, the handler writes one final Ollama-shaped NDJSON line containing an `error` field and stops — it never attempts to change the HTTP status at that point. This is the same in-band-error convention Ollama itself uses and that `ollama.Client.Generate` already parses on the Job path, so no new client-side error convention is introduced.

On a pre-response-body failure (upstream unreachable, non-2xx before any streamed bytes, or `r.Context()` already canceled by yield), the handler writes the same 503 shape `proxy.go`'s `errorHandler` writes today (`X-Broker-Status: deferred`, `Retry-After: 1`) so `Gate`'s trailer/outcome logic — which is driven entirely by context state (`serveDone`, `ctx.Err()`), not by what `next` returns — composes identically regardless of backend. `internal/proxy/proxy.go`'s `errorHandler` body is extracted into an exported `proxy.WriteUpstreamError(w, r, err)` helper so this 503 shape is defined once and reused, not re-implemented in `internal/openaicompat`. `WriteUpstreamError` returns a `bool` indicating whether it handled the error — see the proxy.go Integration point entry for why every caller, including the new handler, must check it.

## Data model
No data model changes. The durable Job store (`internal/job/sqlite.go`, `internal/job/store.go`) is untouched — Jobs remain model/prompt/options regardless of backend (out of scope).

## API / interface contract

**New env vars** (`internal/config/config.go`):
- `UPSTREAM_BACKEND` — `ollama` (default) or `openai`. Any other value: `config.Load()` returns `fmt.Errorf("UPSTREAM_BACKEND %q must be one of: ollama, openai", v)`.
- `UPSTREAM_URL` — OpenAI-compatible upstream base URL (e.g. `http://127.0.0.1:8000`). Required and validated (scheme+host, same as `OLLAMA_URL`'s existing check) only when `UPSTREAM_BACKEND=openai`; unset/invalid in that case is a fatal `Load()` error. Ignored (may be empty) when `UPSTREAM_BACKEND=ollama`.
- `UPSTREAM_API_KEY` — optional. When **non-empty**, sent as `Authorization: Bearer <value>` on every request to the OpenAI-compatible upstream; when empty (or unset), no `Authorization` header is sent at all — the handler must never send `Authorization: Bearer ` with an empty token. The value must never appear in logs (not in `slog` fields, not in error strings — treat it like a secret at every call site that touches it). `config.Load()` rejects any value containing a CR or LF control character at load time (`fmt.Errorf("UPSTREAM_API_KEY must not contain control characters")`), preventing HTTP header injection via a malformed/malicious key value.

**`OLLAMA_URL` becomes conditionally required**, symmetric with `UPSTREAM_URL`: required and validated only when `UPSTREAM_BACKEND=ollama` (the default). When `UPSTREAM_BACKEND=openai`, `OLLAMA_URL` is not required — an operator running pure-openai mode should not have to configure an Ollama upstream they never use. (Today `OLLAMA_URL` is unconditionally required regardless of backend; this plan changes that.)

No changes to `POST /jobs`, `/healthz`'s response shape, `/metrics`' metric names, or `X-Broker-*` header/trailer names.

**`/healthz`** (`internal/admin/admin.go` — `HealthCheck` signature unchanged): the "upstream reachable" sub-check inside `cmd/broker/main.go`'s `healthCheck` closure calls `be.Reachable(ctx)` instead of `oc.LoadedModels(ctx)` directly. Error text changes from `"ollama upstream unreachable: %w"` to a backend-neutral `"upstream unreachable: %w"` (still names the failed dependency generically, satisfying FR-16/AC-9 without hardcoding "ollama").

**Design decision — reject unsupported `/api/chat` fields, don't silently degrade.** If a `/api/chat` request under the `openai` backend contains a field the translator does not know how to forward (most notably a message's `images` array — multimodal is out of scope per the requirements), the handler rejects the request outright with `HTTP 400` and a JSON error body (`{"error":"unsupported field: images"}` or similar), rather than silently dropping the field and returning a degraded text-only response. This is a stated design decision, not an open risk: a Consumer that thinks it sent an image and got a text-only answer back is a worse failure mode than an explicit, immediate 400.

**Design decision — outbound `stream_options.include_usage`.** Every outbound `/v1/chat/completions` request (both the streaming and non-streaming-collected paths) includes `"stream_options": {"include_usage": true}` — the standard OpenAI-compatible convention for opting into a final `usage` block in the SSE stream. This matters concretely because vLLM, the actual target upstream for this feature, omits `usage` by default unless this field is set. The client must NOT assume every upstream honors it, though — some OpenAI-compatible servers ignore unknown fields — so the running per-chunk token counter fallback (below) remains mandatory, not just a nice-to-have.

**Design decision — model names pass through unchanged.** Model names are forwarded verbatim from the Consumer's request to the upstream `model` field, with no translation/alias/mapping layer. This is a deliberate scope decision, not a gap: the operator is responsible for ensuring the upstream's served model names match what Consumers request. A mismatch (upstream doesn't recognize the model name) surfaces as a normal upstream error via the existing error-mapping path below — it needs no special handling.

**Ollama-shaped request/response translation (openai backend only):**
| Ollama shape | OpenAI-compatible shape |
|---|---|
| `POST /api/generate {model, prompt, stream, options}` | `POST {UPSTREAM_URL joined with}/v1/chat/completions {model, messages:[{role:"user",content:prompt}], stream, stream_options:{include_usage:true} (if stream:true), ...mapped options}` |
| `POST /api/chat {model, messages, stream, options}` | `POST .../v1/chat/completions {model, messages, stream, stream_options:{include_usage:true} (if stream:true), ...mapped options}` (messages pass through; Ollama and OpenAI chat message shapes are already role/content compatible for the plain-text case this feature covers; a request carrying an unsupported field such as `images` is rejected with 400, see design decision above) |
| Ollama `stream:true` → NDJSON chunk `{"model","response","done":false}` per token | SSE `data: {"choices":[{"delta":{"content":"..."}}]}` |
| Ollama `stream:true` → final `{"done":true,"eval_count":N,...}` | SSE `data: {"choices":[{"delta":{},"finish_reason":"stop"}],"usage":{"completion_tokens":N}}` then `data: [DONE]` (if the upstream omits `usage` despite `stream_options.include_usage`, fall back to the running per-chunk token count, same as `ollama.Client.Generate` does with `eval_count`) |
| Ollama `stream:false` → single JSON `{"model","response","done":true,"eval_count":N,...}` | non-streamed (or internally-collected) `.../v1/chat/completions` response reshaped into one Ollama JSON object, written once with no NDJSON framing |
| mid-stream failure after chunks already flushed | one final Ollama NDJSON line `{"error":"..."}`, HTTP status unchanged (see Architecture, "Mid-stream error handling") |
| `POST /api/embed {model, input}` | `POST .../v1/embeddings {model, input}` |
| `{"embeddings":[[...],...], "model":...}` | `{"data":[{"embedding":[...]},...], "model":...}` |
| error: non-2xx status | error: non-2xx status → `fmt.Errorf("openai upstream: status %d", resp.StatusCode)` (mirrors `ollama /api/generate: status %d`) |
| error: streamed `{"error":"..."}` chunk | error: streamed OpenAI error event (`{"error":{"message":"..."}}` before any `data:` chunk, or the vendor's mid-stream error shape) → `fmt.Errorf("openai: %s", msg)` (mirrors `ollama: %s`) |
| any path other than `/api/generate`, `/api/chat`, `/api/embed` | `404` — no other Ollama endpoint (`/api/tags`, `/api/show`, `/api/ps`, etc.) exists under the `openai` backend; see Architecture |

**URL construction.** Every outbound URL to `UPSTREAM_URL` (`/v1/chat/completions`, `/v1/embeddings`, `/v1/models`) is built with proper URL joining (e.g. `url.JoinPath` or equivalent), never plain string concatenation/interpolation (`{UPSTREAM_URL}/v1/...`) — string interpolation produces a double slash or a malformed URL when `UPSTREAM_URL` has a trailing slash. `internal/ollama/client.go`'s existing `(c *Client) url(path string)` helper (trims a trailing slash before appending) is the precedent to follow or reuse the pattern of.

## Design decisions
Choices below were previously implicit or under-specified in earlier drafts of this plan; they are now settled:

1. **`openaiBackend.Unloader()` must return a literal, direct `nil`** of the interface type — never a typed-nil concrete pointer. See Architecture, "Typed-nil safety."
2. **`stream:false` is a first-class path**, not an oversight: the handler branches on the incoming request's own `stream` field rather than always forcing `stream:true` upstream and always emitting NDJSON.
3. **Unsupported `/api/chat` fields (e.g. `images`) are hard-rejected with HTTP 400**, not silently dropped with a warning log.
4. **Mid-stream OpenAI-side errors are surfaced in-band**, as a final Ollama-shaped NDJSON `{"error":"..."}` line, exactly mirroring Ollama's own convention — never a second HTTP status after streaming has begun.
5. **The openai backend's outbound HTTP client reuses `internal/proxy`'s `retryTransport`** (connection-level retry before any response bytes arrive) rather than a bare `http.Client`, for the same reasons that transport exists today (see Integration points).
6. **`WriteUpstreamError`'s `bool` return is checked by every caller**, including the new handler — an unchecked `false` return risks Go's `net/http` silently defaulting to `200 OK` on a real upstream failure.
7. **The new package is `internal/openaicompat`, not `internal/openai`** — this is an OpenAI-*compatible* protocol implementation against a self-hosted upstream, never a call to OpenAI's real service, and the package name says so explicitly.
8. **Model names pass through unchanged** (no mapping layer) and **latency-equivalence for the `ollama` backend is verified structurally** (type assertion / code inspection that `ollamaBackend.Proxy()` returns the exact same `httputil.ReverseProxy` built by the unmodified `proxy.New()`), not by wall-clock benchmarking — benchmarking stays out of scope without contradicting a latency requirement, because the requirement is satisfied by construction (same code path, unchanged) rather than by measurement.

## Integration points
- `internal/backend/backend.go` (new) — defines `Backend` interface (`Proxy() http.Handler`, `Generate(ctx, model, prompt string, options map[string]any, onTokens func(int)) (string, error)`, `Reachable(ctx context.Context) error`, `Unloader() Unloader`), the `Unloader` interface (`Unload(ctx context.Context) error` — structurally satisfied by `*ollama.Client`, no import cycle), and `New(cfg *config.Config) (Backend, error)`, the one factory that switches on `cfg.UpstreamBackend`.
- `internal/backend/ollama_backend.go` (new) — `ollamaBackend` struct wrapping `proxy.New(cfg.OllamaURL)` and `*ollama.Client`; `Generate` is the existing `genAdapter.Generate` body moved out of `cmd/broker/main.go`; `Reachable` calls `oc.LoadedModels(ctx)` (same call `main.go`'s `healthCheck` makes today); `Unloader()` returns the `*ollama.Client`.
- `internal/backend/openai_backend.go` (new) — `openaiBackend` struct wrapping `openaicompat.NewHandler` and `openaicompat.Client`; `Unloader()` returns `nil` as a literal, direct interface return (see Architecture "Typed-nil safety" and Design decisions #1 — this is the single highest-risk item identified across review, so the implementation must match that exact form, not just be "nil-ish").
- `internal/yield/yield.go` — small, targeted defensive addition given the severity of the typed-nil risk above: wrap `doUnload()`'s body in a `recover()` that logs (`slog.Error("panic in vram unload", "recover", r)`) and returns rather than propagating, as cheap defense-in-depth for this specific unrecovered-goroutine panic path. This is intentionally minimal — no other refactor of `yield.go` is in scope.
- `internal/openaicompat/client.go` (new package) — `Client.Generate(ctx, req GenerateRequest, onTokens func(int)) (string, int, error)`, signature-mirrors `ollama.Client.Generate` (same params/returns) for symmetry and testability; does the SSE-consuming chat/completions call for the Job path; builds its outbound URL via proper URL joining (not string concatenation, see API contract) and sends `Authorization: Bearer` only when `UPSTREAM_API_KEY` is non-empty; its `http.Client`'s `Transport` reuses `internal/proxy`'s exported `retryTransport`-wrapping transport (see Technology choices) rather than a bare `http.Client{}`.
- `internal/openaicompat/handler.go` (new) — `NewHandler(base *url.URL, apiKey string) http.Handler`, the Synchronous-path translator described in Architecture, including the `stream:false` buffered-response branch and the mid-stream in-band-error branch; shares its SSE-chunk decoding with `client.go` via an unexported `internal/openaicompat/stream.go` helper so the parsing logic isn't duplicated within the new package; its outbound `http.Client`'s `Transport` also reuses `internal/proxy`'s retry transport, same as `client.go`.
- `internal/openaicompat/stream.go` (new, unexported) — helper for SSE parsing shared by `handler.go` and `client.go`: uses `bufio.Scanner` with an explicit `Scanner.Buffer(...)` call setting a larger-than-default max line size (the default ~64KB per-line limit can be exceeded by a single large SSE chunk from some upstreams), and accumulates consecutive `data:` lines into one logical event before a blank-line boundary rather than treating each `data:` line as an independent event (SSE's spec allows a single event's `data:` field to be folded across multiple lines, which some OpenAI-compatible servers do).
- `internal/openaicompat/embed.go` (new) — the `/api/embed` ↔ `/v1/embeddings` request/response reshaping logic. `handler.go`'s `/api/embed` route depends on `embed.go`'s translator existing and being complete — the dependency runs handler.go → embed.go, not the reverse — so `embed.go`'s reshaping logic must be implemented (and testable in isolation) before `handler.go`'s embed route can be considered done. No Job-path embeddings (per out-of-scope).
- `internal/config/config.go` — add `UpstreamBackend string`, `UpstreamURL *url.URL`, `UpstreamAPIKey string` fields; `Load()` validates `UPSTREAM_BACKEND` against the two-value enum, validates `UPSTREAM_URL` (scheme+host) only when the backend is `openai`, validates `OLLAMA_URL` only when the backend is `ollama` (see API contract), and rejects an `UPSTREAM_API_KEY` containing CR/LF — following the exact pattern of the existing `OLLAMA_URL`/`INFINITY_URL` validation blocks.
- `internal/proxy/proxy.go` — extract the body of `errorHandler`'s two matched branches (`context.Canceled`, `context.DeadlineExceeded`) into an exported `WriteUpstreamError(w http.ResponseWriter, r *http.Request, err error) bool` (returns whether it handled the error) so `internal/openaicompat/handler.go` can produce the identical 503/`X-Broker-Status: deferred`/`Retry-After` shape without duplicating it. **Every caller — including the new `openaicompat` handler — must check the returned `bool` and write its own fallback response (e.g. a 502) when it is `false`**; otherwise Go's `net/http` silently defaults to an empty `200 OK` when a handler returns without writing anything, turning a real upstream failure into a false-success response (identified as the runner-up most likely implementation mistake). `errorHandler` itself becomes a thin wrapper calling the exported helper, falling back to its existing 502 branch — no behavior change for the `ollama` backend. Additionally, export (or otherwise make reusable) the package's shared `transport` (`retryTransport` wrapping `http.Transport`, see the existing comment on `var transport` for the 2026-07-15 incident it defends against) so `internal/openaicompat/client.go` and `handler.go` can reuse the same connection-level retry behavior instead of a bare `http.Client`. Check import direction first: `internal/openaicompat` importing `internal/proxy` is fine since `proxy` does not import `openaicompat`/`backend`; if some other cycle concern surfaces during implementation, duplicate the small `retryTransport` type into `internal/openaicompat` instead — reuse is preferred whenever there's no cycle.
- `internal/job/worker.go` — **not modified**, but must remain compile-compatible with the exact `Generator` interface `job.NewWorker` accepts: `openaiBackend`'s `Generate` method (and `ollamaBackend`'s) must match that signature precisely, since `worker.go` is the actual consumer that will call through it in production. Verified by the existing `internal/job/worker_test.go` fixtures plus new tests that swap in a mock openai-compat upstream (see Test doubles below) — this dependency is documented here explicitly rather than left implicit.
- `cmd/broker/main.go` — replace `upstream := proxy.New(cfg.OllamaURL)`, `oc := ollama.New(cfg.OllamaURL)`, `genAdapter{oc}`, and the inline `oc.LoadedModels(ctx)` health check with `be, err := backend.New(cfg)` (fail fast alongside the existing `config.Load()` error path) and `be.Proxy()`, `be` (as the `Generator` passed to `job.NewWorker`), `be.Reachable`, `be.Unloader()` respectively. The `genAdapter` type is deleted (moved into `internal/backend/ollama_backend.go`). `yield.NewWithConfirm(detector, be.Unloader(), ...)` replaces `yield.NewWithConfirm(detector, oc, ...)`.
- `internal/admin/admin.go` — no signature change; `HealthCheck` stays `func(ctx context.Context) error`, satisfied as today by the closure built in `main.go`.
- Test doubles: `internal/openaicompat/handler_test.go`, `internal/openaicompat/client_test.go` use `httptest.NewServer` stand-ins for the OpenAI-compatible upstream (mirroring the existing pattern in `internal/ollama/generate_test.go`), asserting multiple flushed writes (not one final write) for `stream:true` (AC-4) and a single buffered write for `stream:false`, an embeddings round-trip for AC-5, a 400 for a rejected unsupported field, and a mid-stream in-band `{"error":...}` NDJSON line when the upstream fails after chunks were already sent. `internal/config/config_test.go` gains cases for `UPSTREAM_BACKEND=bogus` (AC-2), `UPSTREAM_BACKEND=openai` with missing `UPSTREAM_URL` (AC-3), `UPSTREAM_BACKEND=ollama` with missing `OLLAMA_URL` now being a fatal error, and `UPSTREAM_API_KEY` containing a CR/LF being rejected. `internal/backend/backend_test.go` (new) exercises `New(cfg)` returning the right concrete type, `Reachable`/`Unloader` nil-ness per backend, and asserts (via type assertion / interface check) that `openaiBackend.Unloader()` is a true nil interface value, not a typed nil — a direct regression test for the CRITICAL typed-nil finding. A small number of existing job-worker and proxy-level tests (e.g. Yield-mid-Job preemption, `/healthz` failure naming the upstream) are parameterized or duplicated to also run against a mock openai upstream for AC-6/7/8/9/13, following the existing `internal/job/worker_test.go` fixture pattern (read, not modified, to confirm the fixture shape before duplicating it).
- `internal/acceptance_test.go` (new) — comprehensive integration test validating all 24 acceptance criteria (AC-1 through AC-24) end-to-end with mock OpenAI-compatible upstream, using `httptest.NewServer` for in-process testing.
- `cmd/broker/main_test.go` (new, added post-implementation) — a composition-root smoke test that builds and runs the real binary under each `UPSTREAM_BACKEND` value, asserting clean startup. Added after integration validation caught a real nil-pointer panic on startup under the default backend (`cfg.UpstreamURL.String()` called unconditionally before the backend branch in `cmd/broker/main.go`) that every other green signal (`go build`, `go vet`, `go test ./... -race`) missed because nothing exercised `main()` itself — every other task tested its own package in isolation. This closes that composition-root gap permanently.

## Technology choices
- No new external dependency. SSE parsing is a `bufio.Scanner` over `data: ` lines, the same primitive `ollama.Client.Generate` already uses for Ollama's NDJSON stream — consistent with the constraint that any new dependency must be CGO-free, and simpler than pulling in an OpenAI SDK for two endpoint shapes. The scanner is configured with an explicit `Scanner.Buffer(...)` larger than the ~64KB default, and consecutive `data:` lines are accumulated into one logical event before a blank-line boundary (see `internal/openaicompat/stream.go` under Integration points) — both gaps are known limitations of a naive line-by-line `bufio.Scanner` SSE reader.
- `httptest.NewServer` for the mock OpenAI-compatible upstream in tests (already the pattern in `internal/ollama/generate_test.go` and `internal/proxy/proxy_test.go`) — no new test-double library, and it runs fully in-process (NFR: no real hosted API calls).
- The openai backend's outbound HTTP clients (`internal/openaicompat/client.go`, `handler.go`) reuse `internal/proxy`'s existing connection-retry transport rather than a bare `http.Client{}` — the same class of connection-level failure (a busy shared host dropping a request mid-flight before any response bytes) that motivated that transport for Ollama/Infinity applies equally to a self-hosted OpenAI-compatible upstream like vLLM running on the same shared box.
- Model-name pass-through (no translation/mapping layer) is a deliberate scope decision — see Design decisions and the API contract table.
- The `ollama` backend's latency-equivalence claim is verified structurally, not by wall-clock benchmarking: a test asserts (via type assertion / code-path inspection) that `ollamaBackend.Proxy()` is the exact same `httputil.ReverseProxy` returned by the unchanged `proxy.New()`, which is sufficient given `internal/proxy` and `internal/ollama` are not modified by this feature at all. This keeps "no performance benchmarking in scope" consistent with the latency requirement rather than contradicting it.

## Risk areas
- **SSE chunk shape variance across OpenAI-compatible servers.** vLLM, llama.cpp's server, and others don't all emit identical `delta`/`usage` fields (e.g. some omit `usage` entirely even with `stream_options.include_usage` set, some send an empty final chunk before `[DONE]`, some batch multiple tokens per chunk). The translation logic must tolerate missing `usage` (falling back to a running per-chunk counter, as noted in the API contract table) and an empty `delta.content`. Since only a mock server is available for testing (real vLLM is out of scope), this is the highest-uncertainty area — the mock's SSE shape may not represent every real upstream's quirks, and a genuine vLLM cutover later could surface a translation bug this feature's tests can't catch.
- **Streaming-error detection.** Ollama signals a generation error via a `{"error": "..."}` JSON chunk within an otherwise-200 NDJSON stream (see `ollama.Client.Generate`'s `chunk.Error` check). OpenAI-compatible SSE error conventions are less standardized — some servers send a non-2xx status before streaming starts, others emit an SSE `event: error` or an `{"error":{...}}` payload mid-stream without closing the connection cleanly. `internal/openaicompat/client.go` needs to handle both without misclassifying a real error as a truncated-but-successful stream (which `ollama.Client.Generate` already guards against via its own "stream ended without done" fallback — the openaicompat client needs the analogous guard), and the handler's mid-stream case follows the in-band-NDJSON-error convention described in Architecture.
- **Trailer correctness and single-write discipline for the openaicompat handler's error paths.** `queue.Gate`'s outcome trailer is computed from context state (`serveDone`, `ctx.Err()`), not from what `next` writes — this was confirmed by reading `internal/queue/gate.go`, and is why the plan above claims zero changes to `Gate` are needed. But this composition has only been exercised against `httputil.ReverseProxy` as `next`, which already guarantees internally that it never calls `w.WriteHeader`/writes to the `ResponseWriter` a second time once streaming has begun or after an error response has already been written. The new hand-written `internal/openaicompat` handler gets none of that guarantee for free and must replicate the discipline explicitly: never call `w.WriteHeader` or write to a canceled `ResponseWriter` a second time after streaming has started or after `WriteUpstreamError` has already written a response. Treat this as a testable rule, not just a caution — a dedicated test (yielding mid-stream against the openai backend, asserting no panic, no "superfluous WriteHeader" log noise, and a correct trailer) is required; the AC-7/AC-8 preemption tests can double as this check but should explicitly assert the single-write property, not just the trailer outcome.
- **Two new packages' test surface is large relative to the rest of the repo's package sizes.** `internal/openaicompat` is being asked to do request translation, response translation, SSE decoding, and error mapping for two endpoint families — the existing `internal/ollama` package (202 lines) is a useful size ceiling to aim for; if `internal/openaicompat` grows much past that per file, it's a signal the chat/generate and embed translation should be split into more focused files (already reflected in the file layout above) rather than one large handler.
