## Changes made

- **Fixed a production-breaking ordering bug in `cmd/broker/main.go`'s routes branch.** The original plan decorated `be`/`routeBackends[i]` with activity tracking *after* `backend.NewRouter(be)` and `AddRoute` had already captured those backends by value — meaning a routed vLLM instance (the exact deployment this feature targets) would never have its activity tracked in production and would idle-unload while actively serving live traffic, with no way to wake back up short of a full broker restart. The Implementation Realist and Data Model Critic independently converged on this from two different angles. Fixed by requiring `ctrl` construction, `ConfigureIdle`, and `WithActivityTracking` decoration to happen *before* `NewRouter`/`AddRoute`, and extracting the corrected wiring into a testable `buildBroker()` function (main.go previously had zero test seams).
- **Fixed the `origIndex` mapping direction.** The plan described building a post-filter→orig-index map, but `ConfigureIdle`/`TrackActivity` actually need the reverse (orig→post-filter) to correctly wire idle timeouts onto instances after nil-unloader filtering (e.g. the default Ollama backend, which typically has no `_UNIT_NAME`). Left as-written, this would have silently mis-wired idle tracking onto the wrong instance the moment any instance lacked a `_UNIT_NAME` — again, the realistic topology this feature exists for. Fixed with an explicit orig→post-filter map and a sentinel/bounds-check instead of blind indexing.
- **Closed a negative/zero-duration validation gap that would cause unload/reload thrash.** Three independent reviewers (Scope Auditor, Requirements Auditor, Data Model Critic) flagged that an unvalidated negative `UPSTREAM_IDLE_TIMEOUT` would make the idle-elapsed check almost always true, firing an unload on nearly every detector tick. Fixed: `config.Load()` now rejects negative durations outright, and an explicit zero is defined to mean the same thing as unset (disabled) — resolving both the thrash bug and a separate ambiguity about what an explicit `0` should mean.
- **Fixed a `Router.RoutingSummary()` panic risk.** `RoutingSummary()` uses `Backend` as part of a map key, which requires the dynamic type behind the interface to be comparable. The plan's activity-tracking wrapper would have been incomparable as a struct *value* (it needs to hold a func field); `/status` would panic the moment two or more models routed through a decorated backend. Fixed: the wrapper is now specified to return a pointer, which is always comparable regardless of its fields.
- **Reworded FR11/AC7 to match the plan's own reasoned design instead of contradicting it.** The plan already explains, correctly, that one specific case allows a second, idempotent `Unload` call (Idle fires, then Contention's own unconditional per-instance loop fires again later on an already-stopped unit) — but the original requirements text read as if *any* second `Unload` call were a failure. Reworded to permit that specific idempotent case while still prohibiting an actually-dangerous conflicting/out-of-order pair.
- **Split two oversized, under-tested steps and fixed three dependency errors** in the implementation sequence (a step whose test asserted behavior of code that wasn't implemented until a later step; a step's dependency pointing at the wrong predecessor; two tracks — config.go and yield.go — needlessly serialized when they don't actually depend on each other until they converge at the main.go wiring step).
- **Added a step to update `CONTEXT.md` and write `docs/adr/0016-vllm-idle-unload.md`**, matching this repo's own established one-ADR-per-yield-decision convention (0003/0004/0013/0014/0015) — the original plan cited that convention to justify its design choices but explicitly declined to write the ADR itself.
- **Fixed the rollback plan to lead with the real, zero-code-revert operational rollback** (unset `UPSTREAM_IDLE_TIMEOUT`/`BROKER_ROUTE_<N>_IDLE_TIMEOUT`, restart — disables the feature byte-for-byte per FR4) before falling back to `git reset --hard`.
- **Documented three accepted costs/tradeoffs explicitly instead of silently inheriting them** from ADR-0014 or leaving them undiscovered: the wake path is fire-and-forget (the waking request and others during vLLM's cold-start window will likely get connection errors, same as ADR-0014's existing accepted cost for Contention, just never previously restated for this new trigger); no hysteresis on Idle-firing means a workload with usage gaps landing near the configured timeout will thrash (operator-tuning consideration, not a v1 defect); no new Prometheus metric for Idle events (matches ADR-0014's own no-metric precedent, flagged as a cheap future follow-up if thrash proves hard to diagnose from logs alone).
- **Fixed smaller correctness/precision gaps**: `inFlight`'s decrement must be `defer`-guaranteed (an unguarded decrement could drift permanently negative on a panic path, making the in-flight guard silently useless forever); `startAction`'s doc comment gets updated to reflect its two new legitimate call sites; `trigger` becomes a typed const instead of a bare string; `IdleSummary()`'s nil-vs-empty-slice contract is now pinned precisely; config.go's validation now has an exact, unambiguous insertion point instead of "somewhere near the existing UPSTREAM_UNIT_NAME logic."

## Critiques rejected

- **Security Auditor's `/status` exposure findings (idle-state timing/presence leakage on an unauthenticated endpoint)** — rejected as out of scope for this feature specifically. This repo's `/status` endpoint already exposes equivalent operational detail for existing sections (`routing`, `tdarr`) under the same deliberate, established exposure model (a home-LAN-only broker, not internet-facing, per CONTEXT.md) — this feature's `idle` key doesn't introduce a new risk profile, it extends an already-accepted one. Revisiting `/status`'s auth model as a whole is a separate, larger decision outside this feature's scope.
- **Design Devil's Advocate's suggestion to reconsider vLLM's `/sleep`+`/wake_up` API for Idle specifically** — rejected as an actual design change (this repo has a hard constraint, established in ADR-0014 and restated in this feature's own requirements/plan, against using that API due to the open, unresolved vllm-project/vllm#20627 corruption bug). Accepted only as a documented future-revisit note in plan.md's Risk areas, not a design change now.
- **Design Devil's Advocate's `admin.Mux` positional-parameter-bloat concern** (this is the 4th consecutive feature to add another `func() any` status parameter) — rejected as out of scope. This is a real, valid observation about an existing repo-wide pattern, but refactoring `/status`'s wiring mechanism is a separate concern from this feature and would expand scope well beyond what was asked.
- **Steps & Sequencing Critic's request for a step that deploys to and validates against the real desktop hardware end-to-end** — rejected as a steps.md item; this belongs to (and will be covered by) the ship-it pipeline's later `verify`/deploy/post-deploy-verification phases, which already exercise real behavior against the actual box, not the code-level implementation steps this document scopes.
- **Data Model Critic's `checkIdleLocked` loop-cost-at-32-routes concern** — rejected as a structural fix (adding complexity to guard against a scale this repo isn't at); accepted only as a one-line documentation note, since the existing per-tick lock already does comparable O(N) work for Contention checks at the same N.
